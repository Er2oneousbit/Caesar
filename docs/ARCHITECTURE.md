# Architecture

How Colonia is put together, for whoever touches the code next.

## Big picture

```
            +------------------------- browser only --------------------------+
            |                                                                 |
 index.html |  main.js -> App (app.js) ---- Renderer (render/*)  canvas       |
 or dist/   |               |  \-------- UI (ui/*)            DOM widgets    |
            |               |  \-------- Input (input/*)      mouse/touch/keys|
            |               |  \-------- Sfx, Music (audio/*) WebAudio       |
            +---------------|-------------------------------------------------+
                            v
            +-------------- runs anywhere (browser AND Node) ----------------+
            |  Game (core/game.js)                                           |
            |    map (world/map.js)      typed-array tile layers             |
            |    buildings: Map<id, Building>   walkers: Map<id, Walker>     |
            |    units: Map<id, Unit> (soldiers + raiders), projectiles      |
            |    city: plain object (money, ratings, trade, gods...)         |
            |    systems: sim/*.js       pure functions of (game, ...)       |
            |    events: EventBus  ---> UI/audio/renderer subscribe          |
            +-----------------------------------------------------------------+
```

The simulation never touches the DOM. That single rule is what makes the headless tests (`tests/sim.test.mjs`), the balance simulator (`scripts/simulate.mjs`) and the live main-menu background all work.

## The main loop (`app.js`)

Each animation frame:

1. Add `dt * TICKS_PER_SECOND * speed` to an accumulator and run whole simulation ticks (capped at `MAX_TICKS_PER_FRAME` so a slow frame cannot snowball). An auto-pause stops the loop after the tick that asked for it (below).
2. Keyboard and edge scrolling. Edge scrolling waits for a real pointer move on the current map (`input.mouse.game`): a menu or modal that vanishes under a still cursor only sends `pointerenter`, and its position must not read as "at the screen edge".
3. Render. The leftover fraction of a tick (`alpha`) interpolates walker positions so they glide at 60 FPS even though the sim runs at 12 Hz at 1x. `TICKS_PER_SECOND` only sets the real-time pace: all balance is per tick and per day. Walkers and soldiers count the tiles they walk (`walked`, modulo `STRIDE_WRAP`), and the art swings their legs from that, so steps match ground speed at every game speed and freeze when paused.
4. Refresh UI widgets (HUD 4x/second, info panel ~1.4x/second, advisors every 1.5 s, the Empire map every frame while it is open).

**Auto-pause** (`ui/autoPause.js`, *Settings*): six switches (a fire, a scouted raid or Caesar's legions setting out, raiders or legions arriving, Caesar's request or call for troops, a collapse, an outbreak of disease; only the arrival on by default), stored in `settings.autoPause` and read through `autoPauseSwitches()` so a switch missing from older stored settings takes its default. The sim labels the messages of those events with a `kind` (`core/game.js message()`: `fire`, `scouted`, `legionMarch`, `raid`, `legion`, `request`, `troops`, `collapse`, `disease`); nothing in the sim reads it, so `npm run sim` is unchanged by it. A fire spreading from one already burning is cause `spread` in `igniteBuilding()` (it reads and burns as `fire`, unlabelled). `App.onGameMessage()` pauses when `autoPauseFor(m, settings)` names a switch, only while `app.ticking` (inside step 1): a console command, a test fast-forwarding with `runDays()` and the menu's demo city (never subscribed) do not pause. The loop's guard is `this.game && this.paused`: the menu's demo city ticks whatever `paused` the last game left. The sticky toast it pushes (`Messages.push` with `sticky`, level `pause`; newer toasts trim the oldest that is not sticky) carries the message's place, `empire` or an `open` function (the Imperial advisor for Caesar's letters, the empire map for the legions setting out) for `openMessage()`, and the frame drops it once the game runs again.

**Building to building** (`ui/cycle.js`): `stepOfKind()` (the panel's arrows and `,` / `.`, the panel's *Next idle*) and `stepIdle()` (the `I` key, through `nextIdleFrom()`, and the Production advisor's button, shown only while something is idle), by id within a kind and by `BUILDINGS` order across kinds, wrapping. Idle is `buildingStatus()` red, or amber unless it is only understaffed (the status carries `understaffed: true`). The panel asks the app (`App.buildingPlace()`) for its place among its kind, so `infoPanel.js` and `cycle.js` do not import each other; `App.goToBuilding()` glides there and opens the panel.

## The tick (`core/game.js`)

```
tick():
  time.advance()                          calendar, reports new day/month/year
  updateWalkers()                         movement + arrival logic (incl. ships
                                          and fishing boats: their waits end in
                                          boatAfterWait(), sim/fishing.js)
  updateMilitary()                        soldiers, raiders, wolves (sim/wildlife.js
                                          updateWolves), the fleet and raider
                                          ships (sim/navy.js), towers, missiles
                                          and fire pots
  updatePrefectFights()                   prefects on their rounds fight enemies
                                          within 2 tiles (sim/prefectFight.js)
  updateCriminals()                       prefects and soldiers catch criminals
                                          beside them; every 10 ticks prefects hunt
  for buildings whose phase == tick-of-day:
      kind-specific daily logic (house evolves, farm grows, market buys,
      shipyard builds or sends its spare boat, wharf carts its catch,
      navalia builds a liburnian...)
      updateServiceSpawns()               roaming walkers
      updateLaborAccess()                 can it hire? (housing within 40 road tiles)
      updateRisk()                        fire / collapse
      updateDiseaseRisk()                 homes: disease risk, outbreaks
  on new day:   labor, no-road notices (once per building, after 8 days
                without a road; sim/roadAccess.js), water, desirability
                (if dirty), stats, the city's
                entertainment base and wine sources, goods use on day 8,
                immigration, emigration, fires spreading, sick homes
                (spreading, calling physicians, recovering), home moods
                (day 8), caravans and ships, raid progress (a raid by sea:
                its days from the landing; the warband breaking at its
                people's losses), gladiators turning during a revolt
                (sim/revolt.js revoltDaily), new ships' trips to the Portus
                (sim/training.js updateDrill) and supply demand for barracks
                and the navalia, then Caesar's legions (sim/legion.js
                caesarDaily: the march and its reminders, the siege, its
                end, a new march) and
                the check for a city overrun (the only defeat), then wolf
                packs (sim/wildlife.js wildlifeDaily: a pack moving on,
                growing a wolf back, or gone)
  on new month: food/goods consumption, wages & taxes, army pay (and a
                gladiators' revolt reaching its end month), the
                governor's salary (sim/governor.js, last, so it never makes
                debt), raid
                warnings (sim/military.js raidWarning: the rumour at 6
                months, the scouts at 3, by land or by sea, sim/navy.js
                seaRaidPlan, a month away at 1) and launch, city mood, home moods, religion, ratings
                (then the month's crime flag is cleared), city health (and
                last month's grouped outbreak message), Emperor requests,
                distant battles (sim/battle.js battleMonthly: recalled
                troops coming home, a request, the march, riders carrying
                a recall, the battle, the way home), the count of recent
                gifts, history, the victory check
  on new year:  tribute, ledger rollover, the year's salary against the
                governor's rank (favor), trade quotas reset, the year's
                price news (sim/prices.js pricesNewYear: prices follow the
                date, so nothing changes here), crime and disease counts
  then, on a new day: the crime roll (last, so on the 1st it sees the new
                month's home moods and counts toward the new month)
```

Buildings get a `phase` (`id % TICKS_PER_DAY`) so their daily work is spread over the 20 ticks of a day instead of spiking at midnight.

## Data model

* **Map** (`world/map.js`): one `Uint8Array`/`Int32Array` per layer, index `y * w + x`. Persistent layers: terrain, variant, road, aqueduct, rubble, fixedRoad, wall (wall/gate), roadblock (on road tiles: `ROADBLOCK.PRESENT` plus the bits of the walker groups it lets through; missing in older saves, which load without any). Derived layers (rebuilt, never saved): building ids, desirability, water coverage bits, road network ids, distance to water, **navigable** water (connected to the map edge; ships) with `navBody` (which navigable water a tile is, so warships and raider ships never leave theirs) plus `seaEntry`, and **fishing water** (`fishBody`: every body of water of `FISH_BODY_MIN` tiles or more, labelled) with its `fishingGrounds` (`computeFishing()`: from the terrain and the saved `variant` bytes only, no random draws, so every map stays as it was and old saves get grounds too).
* **Map generation** (`world/mapgen.js`): `generateMap({ width, height, seed, type, regions })`, a scenario's through `mapOptions(s.map)`. The same options always give the same map. `regions` (the last campaign step's maps) gathers the fields, woods and rocky hills each in a region of its own (`REGION_KINDS`): three centres a third of a turn apart on a ring (`REGION_RING` of the side from the middle), turned to keep them on land, each adding up to `REGION_BONUS` to its resource's noise within `REGION_RADIUS`, with `REGION_SHARES` of the land for each; the draws come from a stream of their own (`${seed}:...:regions`), so maps without regions are as they always were. `info.regions` holds the centres (not saved: a save stores the terrain).
* **Ruins** (`sim/ruins.js`): the rubble layer is only a flag; `game.ruins` maps a rubble tile to what stood there (a building name or a home's level name), why it fell (`RUIN_CAUSES`: fire, wrath, raidFire, riot, collapse, raid, raidWall, and legionFire, legion, legionWall for Caesar's legions) and the month and year. Every tile of a footprint shares one record, cleared tile by tile when the rubble is cleared or built over (`clearRuin`; an undo puts it back). Saves hold one entry per record with the tiles it still covers. Words only: the sim never reads it.
* **Building** (`sim/entities.js`): plain object. `b.def` is the static definition from `data/buildings.js`. Every building has a `turn` (0..3, quarter turns clockwise of its art, chosen with R as it is placed: `planAction(..., turn)`, `placedTurn()`; `turnRule()` says which turn themselves, the waterside buildings and the arch, which stay at 0; looks only but for the hippodrome; rubble's `site.turn` keeps it for Rebuild, and the lots a home falls back to or breaks into keep their home's). Kind-specific fields: `house` (tier = housing level 0-20, pop, pantry, service timers (`police`: days of police cover from a prefect), `entBoth` two-show visits, `devolveDays` bad days in a row, `merged` for a 2x2 block of single-tile homes; for crime: `mood` (null while empty), `moodReason`, `moodTarget`, `hungerStreak`, `criminal` 0/1/2; for disease: `diseaseRisk`, `sick` days left), `noRoadDays`/`noRoadWarned` (days in a row without a road, and whether the one-time message went out), `stock`/`incoming` (storage, markets, workshops), `orders` (granaries and warehouses: per good `'accept'`, `'refuse'` or `'get'`), `emptying` (the Empty switch) and `orderNote` (what the last Get or Empty check found, for the panel), `shows` (venues; one count per kind in `SHOW_KINDS`, the hippodrome's races included), `hasWater`, `fertility`; shipyards and wharves: `mooring` (the water tile beside them, cached) and `waterSide` (for the art), a wharf's `boatId` and `catches`, a shipyard's `spareId`, `progress`, `boatsBuilt` and `stock`/`incoming` of timber; the fleet's buildings (on the shore, with `berth` and `waterSide` like a dock): a navalia's `stock`/`incoming` of timber, iron and linen, `progress`, `built` and `blocked`, a naval station's `rally`; a fort's or naval station's `service` (the Empire service switch, `sim/battle.js`); a triumphal arch's `axis` (0: its road runs along x, 1: along y; the arch's middle tiles are building tiles that keep `map.road`, the one place a road lies under a building). Houses change footprint as they grow and split; they keep their id (and the anchor tile) when they do.
* **Linked buildings** (the hippodrome, `span: 3` in `data/buildings.js`): Colonia's footprints are square, so the 15 x 5 hippodrome is three 5 x 5 buildings, the `hippodrome` itself (staff, walker, shows, fire and collapse, info panel; its `parts` list the others) and two `hippodrome_part` (no staff, never burn or collapse; `main` points back, `section` 1 or 2 picks their stretch of the track's art). Turned, the row runs along y (turns 1 and 3) and section 0, the rounded end, sits at whichever end the turn takes the art's start to (`spanLayout()`: the row's size and each section's top-left; `spanOrigin()`: the row's top-left from the main section's; every section has the hippodrome's turn and draws its stretch turned). `linkedGroup()` / `mainOf()` in `sim/entities.js`: `removeBuilding()` takes the whole group, `computeAccessRoad()` takes a road beside any section (`footprintRect()`), a roamer passing a section looks after the main one, flames beside a section heat it, a burned or collapsed section leaves rubble over all 75 tiles whose record rebuilds the hippodrome, `planAction()` previews all three (`items[k].part`, with their `type` and art `state`; `items[0].origin` is the whole row) and `applyPlan()` builds them as one (one cost, one undo). The info panel shows the main section for a click on any part.
* **Walker**: plain object with `kind` = `roamer` (wanders serving buildings), `carrier` (goes somewhere and comes back), `traveler` (goes somewhere and vanishes), `ship` (like a traveler, but its path runs over water instead of roads: merchant ships over navigable water, fishing boats over their own fishing water) or `criminal` (protester, thief, rioter: `sim/crime.js`, with `hp` and the `home` it came from). Movement is always "stand on tile (x,y), walk toward (tx,ty), progress 0..1". A walker with `offRoad` (rioters, and prefects chasing them or walking back from a chase) follows a path over open land (`landPath`: A* with roads cheaper and trees dearer) and only plans again when a building or wall appears on it; `held` > 0 freezes a walker for a tick (a prefect and a criminal in a struggle).
* **Unit** (`sim/military.js`): soldiers and raiders are not walkers. They move freely over open land in continuous tile coordinates (tile centers at .5), fight, and are drawn live by `render/militaryArt.js`. `px/py` keep the previous tick's position so the renderer can interpolate. Ships of war are units too, with `naval` in `data/units.js` (`sim/navy.js`, drawn by `render/shipArt.js`): a liburnian has its `station` and berth `slot` (and a `ramCooldown`), a raider ship its `invasion`, `crew` (the warriors still aboard), fire `pots` and `waitTicks` before it sets out; both follow water routes (`path` over their `navBody`). `updateMilitary()` sorts them out of the land lists, so soldiers, raiders, towers and the crime code never see a ship, and runs them in `updateNavy()`. A Roman unit is `trained` or not (`sim/training.js`), and a new liburnian on its way to the Portus has `drill` (its id) and `drillDay`, and moored there training `trainLeft` (a soldier with `drill`, from an older save, is sent home by `updateRoman`). One sent to a distant battle (`sim/battle.js`) has `away` and `awayTick` while it walks (or sails) out; at the edge it leaves `game.units` and its record (the unit as plain data) travels in `military.battle.sent.men` / `.ships` (or, recalled and turned back, in a `military.recalls` entry) until it comes home and is put back with the same id. Caesar's legionaries (`imperial`, `sim/legion.js`) are enemy units with `legion` (their army's id, never an `invasion`) and `waitTicks` (their turn at the entrance), so raids and legions keep separate counts. A unit's `side` is `rome`, `enemy` (raiders of every people, Caesar's men, rebel gladiators with `revolt`), `wild` (wolves, with `pack` and `prey`, a walker's id) or `native` (native villagers, `attacking` while their village is at war); `hostileToRome(u)` (`sim/military.js`) is the one rule soldiers, towers and prefects fight by, and only side `enemy` holds up a victory or the peace rating.
* **Reservations**: a cart on its way reserves room at its target (`incoming`; a Get cart reserves room at its own building, from the moment it sets off, for what it will bring back), settlers reserve beds (`house.incoming`), performers reserve a venue slot. `killWalker()` always releases them, so storage never overfills and houses never overbook.

Everything is serializable JSON, see `core/save.js`. Map layers are PackBits run-length coded then base64 (`"pb:..."`, or plain base64 when that is smaller) and walker/soldier paths are packed as 16-bit tile indices (`"u16:..."`; maps are at most 256x256, so every index fits). The save format is versioned (`SAVE_VERSION`, currently 21: 21 trade by partner (each trade route's `off`, the goods switched off with that partner, `sim/tradeSwitches.js`); `upgradeTradeSwitchesV20()` gives an older save's routes an empty `off`, every switch on; 20 horses live at the Horse Ranch (a ranch's `incoming`; a new warehouse's `stock`, `incoming` and `orders` have no horses); `upgradeHorsesV19()` moves an older save's warehouse horses to ranches with room, lowest ids first, and leaves what does not fit at its warehouse, whose supply cart takes it on to a barracks that needs it or a ranch with room (an upgraded warehouse keeps a horses entry in `stock` and `incoming`, at 0 once empty, for the old save's carts still on the road, but no order); 17 shipyards hold timber (`stock.timber`, `incoming.timber`); `upgradeShipyardTimberV16()` gives a yard with a boat started (progress above 0) the 100 timber it is built from and the others none, so nothing stalls mid-build (16 is another change's); 15 the staged warnings (`military.warnStage`, `warned.noShore`, `military.caesar.noticeStage`, a message's `empire`); `upgradeWarningsV14()` counts every stage whose moment has passed as given, from the save's own timers (a raid scouted: 2, or 3 a month out; one not scouted 6 months out or less, in a town of `RAID_MIN_POP`: 1; the legions by `noticeStageFor(countdown)`), so nothing is posted on load or late; 14 Caesar's legions, distant battles and triumphal arches (`military.caesar`, `military.battle`, `military.battles`, `city.archesEarned`, forts' and stations' `service`, units' `legion`, `waitTicks`, `away`, `awayTick`, an arch's `axis`); `upgradeEmpireV13()` gives an older save no legions coming, no battle, no arches and every switch off, starts `stats.peakPopulation` again at today's population (a city that had shrunk before the overrun rule existed is not lost to the first raid after loading), and a city saved at favor 0 plays on (the legions set out the next day); 13 the governor (`city.governor`: `rank`, `salaryRank`, `savings`, `paidThisYear`; `city.gifts`: `recent`, `monthsSince`, `sent`, in place of `city.giftCooldown`; 12 is another change's); `upgradeGovernorV12()` gives an older save the mission's rank (a sandbox the middle one) at its own rate, no savings, the salary counted as paid for the months of the year already gone, and a gift still in the old six-month wait counted as one gift sent that long ago; 11 sea raids and the fleet (`military.seaRaids`, the switch; `navalDemand`; ship counts in `stats`; navalia, naval stations, liburnians and raider ships; an invasion's `sea`, `landing`, `landed`, `landedDay`; `upgradeNavyV10()` turns the switch on for older saves, adds the counts at 0, and leaves a raid the scouts already saw a raid by land); 10 the cloth industry (flax, linen and clothing; `upgradeClothV9()` gives older saves clothing at 0 in every market, the three goods at 0 in every warehouse and dock and a trade setting each, and every home clothing at 0 but Tenements and better, which start with `CLOTHING_GRACE_MONTHS` (3) of it so a loaded city has time to build the chain); 9 fish (a fifth food), shipyards, wharves and their boats, and the hippodrome; `upgradeFishV8()` gives older saves fish at 0 in every food list and a fish trade setting, hippodrome access and shows at 0; 8 ships waiting at the dock while dock workers carry goods both ways; 2 added the military, 3 the packing, 4 the 20-level housing ladder, 5 home mood and crime, 6 disease, 7 granary and warehouse orders, ruins (older saves load with rubble that has no record) and the original's five gods, 8 ships that wait at the dock (a moored ship's `unload`, `wants`, running `deal`, `mooredTick` and crane, a dock worker's export `claim`); `upgradeGodsV6()` runs first, on the raw data before anything is built from it, and renames Jupiter to Mercury and Vesta to Venus everywhere a god's key is stored (`city.gods`, the two temple types, every home's `religion`, priests' `god`, a sandbox scenario's unlock list), since the loader skips buildings of an unknown type; then `upgradeV4()` gives version 4 homes the crime fields, `upgradeV5()` gives version 4 and 5 homes the disease fields, and `upgradeOrdersV6()` turns older storage's `accept` flags into `orders` (Accept or Refuse, Empty off), `upgradeShipsV7()` gives a ship moored in a version 7 save (which traded everything on arrival and was logged then) nothing left to trade, so it casts off on the first tick without a second log entry (goods on a quay stay and are carted on), and the Game constructor fills in `city.crime`, `city.health`, any god a save lacks and `city.venusBoost`). Until 1.0 a release may refuse older saves (`MIN_SAVE_VERSION`, now 4), always with a readable message; fields added within a version get fresh defaults when missing. Campaign saves store only the mission id plus `difficulty`; sandbox saves store their whole scenario.

**Difficulty** (`data/difficulty.js`) is one table of levers per level (funds, risk, production, winter farm growth, immigration, mood, raid size/interval, raider strength, the Emperor's request size/interval/deadline, crime, disease, and the favor bands that send Caesar's legions home or halt them, `legionHome` and `legionHalt`, in points). `Game` looks the level up once (`game.difficulty`, from `scenario.difficulty`) and each system reads its own lever; campaign missions get a level through `withDifficulty()` (`data/scenarios.js`), which also scales their funds.

## The genre mechanics, where they live

| Mechanic | File | Short version |
|---|---|---|
| Service coverage | `sim/services.js` | Roamers set per-house access timers (96 days; tax registration 48) on buildings within 2 tiles of each step. An entertainer from a venue with both kinds of show booked also sets that venue's `entBoth` timer. |
| Roaming | `sim/movement.js` | Never reverse, prefer straight, avoid recently walked tiles, stay within 13 tiles of home; the street weights are worked out only at a junction (with one way on, it is taken whatever it weighs, and the dice are thrown all the same); prefects and engineers weigh each way by the worst fire or collapse risk along it, to the next junction (`streetRisk`, up to 11 times as much at the threshold); every other service roamer weighs it by the neediest home along it (`homeNeed`: how far his access timer has run down, or for a market vendor how short its pantry is of what his market has, `sim/market.js` `vendorNeed`), looking past junctions over every road within 8 steps, a home k steps on counting 1 - k/16 of its need and a home more than 13 tiles from his building nothing (`streetNeed`, up to 41 times as much: `SERVICE_PULL`); prefects, engineers, priests, tax collectors, barbers, physicians and bath attendants start their next round as the last one heads home (`sim/services.js` `OVERLAP_ROUNDS`); never step onto a roadblock (`map.roadblock`) that does not let the walker's group through (`data/walkers.js` `ROADBLOCK_GROUPS`). Walkers following a path (to a destination or home) ignore roadblocks. |
| House levels | `sim/housing.js`, `data/housing.js` | 20 levels. Up one level at once when the next level's needs and the current level's `up` desirability are met; down one after `game.difficulty.devolveDays` bad days in a row. Four single-tile homes of a level may join a 2x2 block; homes grow into 2x2 / 3x3 / 4x4 at 11 / 15 / 19 (homes of their level or lower, then clear land, then gardens; partly covered homes break up) and split when they fall back, keeping a corner with a road in reach (pieces with no road stay vacant lots). Residents over capacity leave as homeless. |
| Entertainment | `sim/entertainment.js`, `sim/housing.js` | A home's score = the city-wide base (0-20 from the three seat kinds' coverage over the population, daily; a working hippodrome adds 100% coverage to the sum, still over `ENT_SEAT_KINDS` 3, so up to `ENT_BASE_MAX` 26) + points for each venue visited (+ a bonus when it had both kinds of show; the hippodrome's charioteer 30). A venue sends its walker only while staffed and booked; the chariot maker books the hippodrome's races (`racesRunning()`, which also lifts the prosperity target by `HIPPODROME_PROSPERITY`). |
| Fishing | `sim/fishing.js`, `world/map.js` | Shipyard: progress by staffing x production, a boat every `SHIPYARD_BOAT_DAYS`, only while it holds `SHIPYARD_BOAT_TIMBER` (100) timber, used at launch (Colonia's own rule; logged as used). Timber comes in the workshops' delivery tier (`storage.js` `rawRoomCap`/`rawHasRoom`: producer carts, dock wagons and `updateWarehouseSupply`, nearest first), up to the yard's `inputCap` (200); the boat waits as the yard's spare until the nearest staffed boatless wharf on its water (by water route) takes it (ownership moves to the wharf, so it sinks with it). Wharf's boat: moored for (1.02 - staffing) x `BOAT_WAIT_DAYS` (not with no staff, not while the wharf holds `WHARF_FULL`), to the nearest ground by water, `FISH_DAYS` / production fishing, home, `FISH_CATCH` landed; the wharf ships it like a farm (`shipOutput`). Neptune's wrath: `sinkFishingBoats()`. Guards that keep a city with no fish exactly as before: market buyers want fish only when some storage holds it (and clothing likewise, wanted by Tenements long before a city makes any; the Emperor asks for flax, linen or clothing only while a building that makes it stands, so a city without the cloth industry draws its requests as before), Mercury gives `LAND_FOODS`, the Emperor asks for fish only while a wharf works, the capacity model leaves wharves out. |
| Immigration | `sim/population.js` | Mood >= 30 and free beds on the entrance's road network; groups walk in from the map edge. Past a 70-tile trip they ride a mule, up to 2x faster (big maps). |
| Labor | `sim/labor.js` | 32% of plebeians work; priorities first, then proportional shares. |
| Water | `sim/water.js` | Reservoir next to water fills; aqueducts flood-fill to more reservoirs; piped area feeds fountains/baths. |
| Desirability | `sim/desirability.js` | Every building radiates `[value, step, stepSize, range]`; terrain adds waterfront/tree bonuses. |
| Home mood | `sim/mood.js` | For crime only. Twice a month each home moves at most `MOOD_STEP` toward city mood + hunger streak + food variety + envy (the poorest levels in a rich city) + desirability + untaxed, and records its worst trouble. |
| Crime | `sim/crime.js`, `data/crime.js` | Daily from 300 people (off in missions with `crime: false`): the lowest-mood home that can still produce something; the chance falls on one line with city mood, x `difficulty.crime`, halved by police cover (a prefect within `POLICE_DAYS`). A protester stands about 4 days; a thief walks to a Forum/Senate (else a market) and steals on arrival (never more than the treasury holds); a riot burns its home and sends a mob overland at the most prized building within 40 tiles (`RIOT_TARGETS`), else the nearest listed one it can reach (`nearestReachableRiotTarget`, a search over open land), burning what it passes, for at most `RIOTER_MAX_DAYS`. Prefects and soldiers beside a criminal catch him; roaming prefects hunt thieves and rioters within 30 tiles, and one they cannot reach is skipped for `HUNT_RETRY_TICKS` (`walker.noChase`) while they keep their patrol. A family moving into an empty home starts at the city mood with a clean record (`newHousehold`); split-off homes keep their families' mood and record, joined homes the worst flag. Counts per year in `city.crime`. |

| Trade demand | `sim/tradeDemand.js` | Pure, never saved: what a partner buys in force (`buysInForce(scenario, seed, partner, month)`, `partnerBuys(game, id)`): its `TRADE_PARTNERS` table, the scenario's `demand`, then each `demandChanges` entry from its month (`(year - 1) * 12 + demandChangeMonth`, Martius to October, drawn from the map's seed on a stream of its own, as distant battles draw their months). `routeInterval` (which counts only the goods switched on with the partner, `sim/tradeSwitches.js` `onlyOn`) first stretches the usual range for distance (`usualInterval(kind, trip)`: `[max(a, 2 x trip), that + (b - a)]`, `trip` = `tripDays(site, partner)`, Colonia's own rule), then scales it by `carryPerYear(kind, trip) / routeVolume` (the larger of buys and sells) when that is under 1, else returns it, so where the round trip fits (every route from the Etruscan coast) the game's draw is unchanged. `visitsPerYear` (the capacity model's dock count) leaves distance out; `tradeMonthly` (`sim/trade.js`) tells the player of a change in its month. |

## Rendering (`render/`)

* **Projection**: tile (x, y) top corner at world pixel `((x - y) * 32, (x + y) * 16)`. Camera scale = zoom x devicePixelRatio; everything is drawn in device pixels for crisp art.
* **The view turn** (`view.js`; rendering and input only, the sim never sees it): the city seen from any of four sides, `camera.turn` 0..3 quarter turns clockwise on the screen, the same turn `turn.js` gives building art (turn 1 takes +x to +y). The renderer works in **view tiles**: a W x H map at turn t is a W' x H' map (W and H swap on an odd turn), map point (x, y) going to (x, y), (H - y, x), (W - x, H - y), (y, W - x) at turns 0 to 3 (`toView`, `fromView`, `viewTileOf`), and the projection above applies to view tiles, so world px are the turned view's. The camera maps through it (`mapToWorld`, `worldToMap`, `screenToTile`, `centerOnTile`, `glideToTile`; its bounds are the view map's), and `setTurn()` keeps the map point in the middle of the screen where it is (an instant swap, as the original). The ground pass walks the view's rows and finds each map tile with `tileAxes()` (two multiply-adds, no allocation), so its cost is that of turn 0; `viewTiles` stays a map-space rectangle for the passes that loop over map tiles (`mapRectOfView`; with the camera looking past the edge it stays empty). Depth is the view's x + y (`stripsFor` cuts a building from its footprint's view corner, `viewFoot`; walkers' `walkerWorld(w, alpha, t, W, H).d`; a bridge deck's `bridgeSpan(..., t)`; ghosts by `ghostOrder(items, t, W, H)`). Neighbour masks are worked out on the map and rotated (`rotMask`: N becomes E at turn 1; `rotNibbles` for an aqueduct's links and reservoirs and a blend's edges and corners; `rotBlend`; `viewAxis` for bridges and roadblocks), so a turned tile uses the sprite and key a turn-0 tile of that shape uses: no new ground keys. A building is drawn at its footprint's view corner (`Renderer.footAt`) with its art at `artTurn(b, t)` = `(b.turn + t) & 3`, and so are its flags, altar flame, crowd, stock, kiln smoke, forge sparks and night lights; a hippodrome's races face `raceSpot(..., t)`'s direction. Walkers face their map step turned (`viewDir`; standing, their `lastDir` turned). Soldiers, raiders and ships: the sim's `u.facing` is the unturned screen's, so the renderer keeps each unit's last heading (`Renderer.headings`, render state only) and `unitFace()` turns it: the way it moved, or toward the foe it stands and fights (`u.target`), giving way to the sim's facing when they disagree (a raider turned to strike a building); `drawUnit` and `drawWarship` take that facing, `drawProjectile` the turned velocity. Map gates turn their pillars (`mapGateOffset(..., t)`); tile sides for outlines go through the camera, so overlays, coverage, hints, ranges, the ghost and its footprint, the no-road edges, selection outlines and rally lines all follow. The **minimap** turns with the view (as the original's): it is drawn row by row of the view, so a turned minimap is the unturned minimap of the turned map, the camera frame stays a rectangle and a click maps straight to world px; an N marks north. North is the game's compass (`sim/military.js screenDirection`: straight up at turn 0, the map's (0, 0) corner), which the top bar's needle (`Hud.showViewTurn`) also shows. Input: `Q` / `]` and `Shift+Q` / `[`, the top bar's buttons and the console's `view` call `App.turnView()` (a held key turns once), which turns the renderer and calls `Input.rehover()` (the tile under a still cursor changed); scrolling stays screen-relative. The turn is saved with the camera state (`Camera.serialize()`'s `turn`; a save without it opens at 0) and `Renderer.attach()` starts every game unturned; nothing in the sim depends on it (`tests/view.test.mjs` checks a game is unchanged by turning).
* **Camera** (`camera.js`): `zoomIndex` is the zoom level the player picked; `zoomF` is the zoom shown, which eases to the level in about 0.2 s with the point under the cursor pinned. Also a fling (drag velocity that decays) and `glideToTile` (eased travel, used by messages, advisors, the minimap and Home). `centerOnTile` and setting `zoomIndex` stay instant (loads, tests). `smooth = false` (reduced motion) makes everything instant. `update(dt)` runs once per frame from the renderer.
* **Sprites**: every piece of art is a `spec` (size, anchor, draw function) rendered once per zoom level into an offscreen canvas (`sprites.js`). Art is procedural (`terrainArt.js`, `buildingArt.js`) using the tiny iso kit in `draw.js` (boxes with wall texture and contact shadows, tiled roofs with eave shadows, columns, windows with optional shutters and flower boxes, trees). Sprites are made for the zoom LEVEL and remember their scale `s`; while a zoom eases, `blit()` stretches them by `scale / s` (building strips snap to whole pixels so they do not show seams). New sprites get about 8 ms per frame (`spriteBudgetMs`); past that the cache borrows the other kept zoom level's copy, so a zoom never stalls while hundreds of sprites are drawn, and they sharpen over the next few frames.
* **Draw calls**: keep them down in the per-tile passes. Chromium flushes a canvas mid-frame past a few thousand draw calls, which roughly doubled the frame time when zoomed out, so edge blends are painted into the ground tile's sprite (`groundBlendSpec`) instead of drawn as a second sprite. Test zoomed-out views (`zoom=0`) after adding anything per tile. Turning the view adds no draw calls: with the whole Large map on screen at the widest zoom (4200 x 2200, the demo city, so every turn draws the same things) a frame took 94.8 ms unturned (94.5 before the view could turn) and 95.0 to 95.8 ms at turns 1 to 3 when it came in. On a 1600 x 900 screen the odd turns frame a differently shaped piece of the map (a quarter turn of the tiles is not one of the screen), so they can hold more objects and cost more for that alone (22.8 ms unturned, 23.3 to 24.1 ms turned, on Large).
* **Depth sorting**: flat things (terrain, roads, rubble) draw first. Everything tall is sorted by the x + y of its front point (in view tiles: the painter's order turns with the view). Multi-tile buildings are cut into half-tile-wide vertical **strips**, each sorted by the front-most footprint tile it covers. That is what lets a walker pass correctly in front of and behind a colosseum with a simple sort.
* **Overlays** (`overlays.js`): tile tints and info columns; non-relevant buildings drawn as flat footprints. The crime overlay's columns and words come from `ui/crimeInfo.js`, the health overlay's (disease risk, sick homes in `SICK_COLOR`) from `ui/healthInfo.js`; the Problems overlay (`ui/problems.js`) puts sick homes and homes in unrest ahead of what a home lacks.
* **Turned art** (`turn.js`): any building can be drawn turned 0 to 3 quarter turns clockwise (turn 1 takes the art's +u edge to +v), a pure function of its art and the turn, so the view rotation can draw a building at `(b.turn + view turn) & 3` with no art of its own. Art is still written for turn 0, back to front. `buildingSpec(..., turn)` draws through `drawTurned()`: at turn 0 it draws straight onto the canvas as it always did; turned, `P()` and the primitives turn (u, v) inside the footprint (`turnUV`), `box()` and the roofs turn their rectangle and draw the faces seen after the turn (an odd turn swaps a gable's ridge axis), `windows()` show on the seen face of their axis (a wall's windows run all round it), and `door()` stays where it is: turned away it is drawn on the hidden face, under the walls, and records no night light. Meanwhile the canvas is a recorder (`TurnRecorder`): every paint call is kept with its state and path in **units** (one primitive each, or the direct canvas calls that follow the `P()` points that placed them, as tall as 12 px unless they lie flat on one wall), each with its box in turned (u, v, z); `sortUnits()` orders them back to front (A first when it lies wholly on the far side of B along u or v, or below it along z; units apart on the screen are left alone; two that overlap keep their drawing order, unless one is a face (`decal()`, or a flat vertical polygon), which goes in front of what is on its inner side and behind what is on its outer side once it looks away), then the recording is replayed onto the canvas. Hand fixes for art that assumed its facing: a gable's pediment and its emblem, the arch's face and the big statue's inscription are `decal()` faces; the theater's bowl is drawn through footprint points; the iron mine's hill has its far sides; the ranch fence goes rail by rail; a 2x2 block of homes draws each home in its own square (`withOrigin()`); round or square-symmetric buildings (`SAME_EVERY_WAY`: the well, fountain, reservoir, arenas, oracle and small statue) draw as written at any turn. Live details turn too: flags (`flagsFor(type, size, turn)`), the altar flame (`templeAltar(S, turn)`), kiln smoke and forge sparks, the theater's crowd, night windows and torches (`lightsOf(..., turn)`), and the warehouse's and granary's stock (`drawTurnedOver()`: the stock and the building's own walls, recorded once per type, turn and snow, sorted together; only the stock is painted, each piece followed by the walls in front of it that overlap it, so a wall in front covers it again and nothing translucent is painted twice). Round buildings' night torches stay put (`lightsOf` uses turn 0 for `SAME_EVERY_WAY`), and a hippodrome's ghost is drawn back to front (`ghostOrder()`). The races are laid on the turned track by `raceSpot()`. `tests/e2e/artsheet.html?turns=1` shows every building and home level at the four turns (`turns=temple,farm` for some kinds, `snow=1` under snow) and the whole hippodrome each way.
* **Building sprite keys** are `b:{type}:{size}:{variant}:{state}` (`buildingKey()` in `renderer.js`; `state` from `artState()`: a home's level, a farm's growth...), then `:t{turn}` for a building drawn turned (`turnKey()` of `artTurn(b, view turn)`, its own turn plus the view's; nothing at 0, so unturned keys are as they always were, and a building turned 3 seen at view turn 1 shares the unturned sprite), then `:sick` for a sick home (drawn a little pale with a pale cloth on a pole, `sickSign()` in `buildingArt.js`), then the snow suffix `~n{level}`, which stays last so a look change can drop sprites by suffix.
* **Fishing and races** (looks only): a fishing boat (`drawFishingBoat()`) shows its state (sail up under way, the net cast with a ring of floats while fishing, a basket of fish on the way home); gulls over each fishing ground (`drawGulls()` in `waterArt.js`, `Renderer.drawFishingGrounds()`, drawn still with reduced motion). The hippodrome's three sprites share one design (`hippodromeArt.js`, state = section). While races run, three chariots lap the spina (`Renderer.raceItems()`): each is queued just after the strip of its section's sprite that holds it (strips are screen columns drawn at their front tile's depth), or the track would paint over it. The charioteer and a chariot maker's team are drawn as a chariot and pair (`drawChariot()`). The shipyard's art state is its water side plus the hull on the slip (none, ribs, planked); the wharf's its water side plus baskets of fish while it holds a catch.
* **Walkers** are drawn live each frame (`walkerArt.js`), not cached, so they have no sprite keys. A walker type's `item` picks what it carries; the criminals have their own: a protester shakes a `placard`, a hooded thief carries a `sack`, a rioter waves a flickering `torch` (the raised arms bob with the clock, visual only).
* **Carts** show their cargo (`render/cargoArt.js`): each good has its own item (sacks of wheat, crates of vegetables and fruit, baskets of olives and grapes, joints of meat, clay lumps, logs, iron ingots, marble blocks, pots, pale oil and dark wine amphorae, tables and chairs, shields with spears, sheaves of arrows, bundles of flax with blue flowers at their heads, bolts of linen, stacks of folded clothes in two dyes) in a `layout` (`pile`, `row` or `layers`); a good missing from `CARGO_ART` gets a block in its `GOODS` color. The load shows as 1 to 4 items against what the cart holds (`cargoLevel`), and what it holds depends on who sent it (`cartCapacity`: a farm's wagon `FARM_CART_LOAD`, a warehouse's single lot `CART_CAPACITY`, everyone else `CART_LOAD`), so the renderer passes the sending building's def to `drawWalker`. A farm's cart is a longer four-wheeled wagon drawn by an ox; horses (`LED_GOODS`) are led on a rope behind the drover, one per 100 units, and a ranch's drover walks home with only the rope. A caravan's mule carries plain bales on its way in and, on its way out, the goods it bought (`walker.packs`, set by `caravanArrive()`; art only, the sim never reads it; saved with the walker, and a save without it just shows bales). All of it is a few shapes per item, drawn live; `tests/e2e/artsheet.html?carts=1` shows every good at two loads, both facings.
* **Life in the picture** (visual only, never touches the sim): buildings cast soft shadows to the lower right (drawn after the ground, before objects; `shadowLength()` in `buildingArt.js`); new buildings rise out of the ground with a dust puff; forests sway using 5 cached wind frames whose phase rolls across the map; water glints; working fountains spray; fires glow and throw embers; homes smoke; smithies throw sparks. `ambient.js` draws drifting cloud shadows and passing birds. Settings can turn the ambient layer off, and the OS reduced-motion preference disables all decorative motion.
* **Live details** (`liveArt.js`): drawn every frame on top of their building as `K_EXTRA` items right after its strips: flag cloth (the sprite only has the poles when drawn with `live = true`; `FLAG_SPECS` in `buildingArt.js` lists every flag), shoppers along the front of a stocked market, spectators in theaters and arenas while a show is booked (seats hidden by the stage or the arena floor are skipped), the temple altar fire.
* **Terrain**: 8 ground variants per land type. Where two kinds of ground meet, a wavy fringe of the stronger one (forest floor > grass > meadow > sand > rock, `BLEND_RANK`) is painted onto the weaker tile. The packed blend code per tile is cached (`Renderer.blendAt`) until `map.revision` changes.
* **Order of a frame**: ground, building shadows, sorted objects, particles, cloud shade and birds, then the **night** (`lighting.js`: the scene is multiplied by a half-resolution light map filled with the sky tint plus warm pools of light, then window/torch/fire glows are added), then **rain/snow/lightning** (`weather.js`), then the red **no-road signs** (`drawNoRoadSign()` in `liveArt.js`, over every building in view for which `lacksRoad()` holds; never smaller than its zoom-1 size, about 20 CSS px across, shown under overlays too; `stats.noRoad` counts them), then tool previews, radius hints and selection outlines, so those are never darkened. A building ghost on a spot with no road it could use is drawn in the warning color (its own sprite key, `...:noroad`, before the snow suffix; `tintedSpec()`), with the edge tiles where a road would serve it picked out (`accessEdgeTiles()`; `stats.ghostNoRoad`, `stats.roadEdges`), and `ui.js` puts the warning by the cursor in the tooltip's `warn` style.
* **Day, season, weather** are derived per frame in `Renderer.updateEnvironment()`: time of day from `game.time.totalTicks` (`dayTime`, `DAY_TICKS`), the season palette from `game.time.month` and the snow cover level (`seasonPalette(month, snow)`; `MONTH_LOOK` places each month among the four looks, and ground/tree/blend sprite keys end in `~p{look}[n{snow level}]`, building and rock keys in `~n{level}` while snow lies), and the weather state machine advanced by the game ticks that passed (so it pauses with the game). Seasons are calendar data (`sim/time.js` `seasonOf`, `SEASON_NAMES`, `GameTime.season()`; Dec-Feb winter, Mar-May spring, Jun-Aug summer, Sep-Nov fall); `weather.js` re-exports them. The weather draws a new spell when the season changes and `seasonalKind()` keeps rain and storms out of winter and snow out of the other seasons; `Renderer.attach()` calls `weather.reset()` so a new or loaded game opens clear and without snow. Snow **cover** (`weather.cover`, 0..1) builds while it snows and melts after (slowly in winter, fast in spring); it is quantized to `coverLevel` 0..3 with a little hysteresis, and the art bakes it into the sprites (white ground, snow-capped trees and rocks, snow on roofs via `setRoofSnow()` in `draw.js`, white fields), so there are no extra draws per frame. A **look change** (new month or snow level) is prepared, then swapped: `SpriteCache.get(key, spec, fallback)` keeps returning the old look's sprite while the new one is drawn within a 4 ms budget per frame (`pending` counts what is missing); the first frame that ends with nothing pending drops the old sprites (`finishLookChange`), so the next frame shows the new look whole. When changes overlap (snow deepening again before the last level is ready), `lookStep()` keeps the complete old look as the stand-in and drops the half-made one. A new or loaded game switches at once (`lookHard`). Window positions for night lights come from the art itself: `draw.js` records where `windows()` and `door()` put openings when the art is drawn into `recordingContext()`.
* **Coverage hints**: clicking a well/fountain/reservoir, or placing one, paints its supply area (dark blue) over the area already covered by that kind (pale blue, read from the sim's water layer). **Water hints** (`waterHintLayers`): while a tool is in hand, the water already there is tinted faintly under everything else: with the Housing tool, well water (palest) and fountain water (a stronger blue); with a building that needs piped water (fountain, baths), the reservoirs' piped area. Each tile is filled once with its strongest layer, each layer gets a thin outline, and tiles the coverage preview paints are left to it (`drawWaterHints`, counts in `stats.waterHint`).
* **Aqueducts** (`terrainArt.js` `aqueductSpec`): cached sprites keyed by their connection mask (`aqueductMaskAt`: the low four bits are the connections, the next four mark which of them are reservoirs, where the channel steps down to the rim) and by whether the tile is a road (a straight aqueduct over a road is drawn as a bridge with one wide arch).
* **Temples** (`buildingArt.js` `TEMPLE_LOOKS`): one look per god (roof, walls, pediment and emblem, a piece in front). The pediment is the god's color (`GODS[g].color`, which its priests wear), and no two roofs or pediments are near the same color (a test holds them apart), so the five read apart in the build menu's small icons.
* **Military layer** (`militaryArt.js`): walls/gates are cached sprites keyed by their neighbor mask (like aqueducts); soldiers, raiders, arrows, sling stones, fire pots and rally flags are drawn live each frame and depth-sorted with everything else. Ships of war (`shipArt.js`: the liburnian's two banks of oars stroke with the distance rowed, its sail furled in battle and at rest; the raider ship shows the warriors still aboard) are drawn the same way; the renderer keeps where each was drawn (`shipSpots`) so a click picks one (`pickShip`) for its panel. A selected naval station shows the water its squadron guards (`drawSeaGuard`). The Navalia and the Naval Station are cached sprites (`navyArt.js`), turned to the water like the dock (`state` = `waterSide`, plus the hull on the navalia's slip). Caesar's legionaries are drawn as Roman soldiers (armor, helmet, the legionary's shield and sword) in purple with a white plume, never with the raiders' hair, over the enemy's red shadow. A triumphal arch (`triumphalArchArt`, `state` = `axis`) leaves its middle strip unpainted so the road drawn on the ground shows through, with the piers either side, the attic and its gilded team on top, the vault's curve on the face the road comes out of.
* **Empire map** (`ui/empireMap.js` draws it, `ui/empire.js` is the full screen): one renderer for the Trade advisor's small map (a snapshot) and the Empire screen (redrawn every frame), in a 100 x 60 map-unit space. The geography is `data/empireGeo.js`: coasts, islands, gulfs, rivers, mountain rows and region names written as longitude and latitude and projected equirectangularly (10 W to 37 E, 48 N to 26.5 N, so a degree of longitude is about 0.76 of one of latitude, true near 40 N); `at(lon, lat)` places a city (`pos` in `TRADE_PARTNERS`, `SITES`, `ROME_POS` all use it) and `isLand(p)` answers land or water by point in polygon (the sea ring less the islands, plus the Red Sea gulfs and lakes). Each partner's route comes from `routePath(site, id)` (`data/empireRoutes.js`: the shortest way over the roads or lanes from the province's site, drawn as a curve), which keeps caravans on land and ships on water; a test walks every curve of every mission's site and every sandbox site, and the star is drawn at the site (`homeSiteId`). Names are placed last (`placeLabels`): each on the first side of its marker where it hits no other name or marker. Travelers are read from timers the sim already keeps, never simulated: `empireTravelers(game)` puts a caravan or ship on its route for the last `shownTripDays` before the route's `nextVisit` (its `tripDays`, at least 2, never more than the shortest gap between visits, so a route has at most one traveler out), positioned by the share of the trip done along the curve, with the day's fraction from `time.tick` so it glides. Until a route's first trader has called (`visits` 0) it is shown over `firstVisitDays` (`sim/trade.js`): that trader set out the day the route opened, so it starts at its city rather than partway along. A warband closes in over the `RUMOUR_MONTHS` (6) before `nextRaidMonth`: while only rumoured (`warnStage` 1, no `warned`) from the site's `frontier` (`frontierDir`) with no number, once scouted (`military.warned`) from its compass side, half way in at the scouts' report (one coming by sea, `warned.sea`, sails in a longship on the nearest side round from it whose whole way in is sea; one by land walks on the nearest side whose way in is all land; from a little nearer where no side is: `warbandPoint(site, dir, frac, sea)`); raiders in the province show beside the city, as do Caesar's legions camped there, each on the first spot over land (`markerSpots(site)`). Armies (`empireArmies(game)`): Caesar's legions on the road from Rome to just short of the province (`legionRoad(site)`, along the roads) by the share of their countdown gone (`legionSummary`), then beside it while on the map; a distant battle's threatened city (`drawBattleCity`), the enemy on its straight line (`enemyLine`) by `enemyToGo`, and the province's troops on their way (`marchLine` smoothed, gliding toward next month's place) or home (`homeIn` of `homeTotal`), from `battleSummary` (`sim/battle.js`). It is pure (tested in node: `tests/empire.test.mjs`, including that reading it changes no state). A message with `empire` (a traveler kind) opens the screen with that traveler picked out (`EmpireView.focus`: hovered, so ringed and read out) instead of gliding to a tile (`ui/messages.js openMessage`). Figures and labels grow on small canvases (`figureScale`) and clicks are tested against the middle of a figure as drawn (`figureCenter`). The screen is modal kind `empire`: like the Advisors the game runs behind it and the keyboard shortcuts work (`App.blockingModal`); its side panel sections are rebuilt only when their text changes, and not while a press inside the panel is held (the days tick by every second or two, and a button rebuilt between press and release would never get its click).
* **Map gates** (`liveArt.js` `drawMapGate`, `K_GATE` items): a stone gateway over the Imperial road at `map.entry` (green pennants) and `map.exit` (red), with torches at night. Mapgen lays the road straight in from the edge for `ROAD_STUB` tiles at each end, so `map.entryDir` / `map.exitDir` (saved with the map) always point straight in and the gates face the edge; `mapGateOffset()` stands the pillars across the road (older saves work the direction out from the roads around the tile); each gate is two items (back pillar, then lintel and front pillar) so walkers pass between them.

## Audio (`audio/`)

* **Sound effects** (`sfx.js`): a few oscillators or a noise burst per sound. The app suspends the audio context while the tab is hidden.
* **Starting the sound**: browsers hold audio back until a user gesture. `App.tryAutoplay()` creates the context at boot (and when a background tab becomes visible) if the music would be heard; where autoplay is allowed it simply runs. Otherwise the main menu shows the **title gate** (`ui.js` `showAudioGate`, `menus.js` `titleGate`): its click, tap or key press starts the menu music, and a short guard afterwards swallows the rest of that gesture (a double-click's second click, a held key's repeats) so no menu button is pressed by it. Unlock listens to `pointerdown`, `pointerup`, `touchend`, `click` and `keydown` (a touch only counts on its release); the context's `statechange` drops the gate whichever way the sound started.
* **Music** is generated, never recorded, in three layers:
  * `composer.js` writes the notes and nothing else (pure, deterministic for a random source, tested in node). A `Piece` has a mood (tempo range, meters, modes, keys, lead instrument, drum and lyre styles, the silence after it, a target length), an opening (`INTRO_STYLES`: who starts), and a form built to the target (a few minutes): the opening, then rounds of 4-bar sections repeated until it is long enough (A the theme, A2 moved up or down, B a higher answer, C a calmer contrast on the other pipe with a thinner accompaniment, an interlude for the lyre alone, A3/A4 ornamented), then an ending (battle music has none). A one-bar theme returns varied in the A sections; harmonies are perfect fifths under a drone; melodies move mostly by step, put chord tones on strong beats and long notes, and end phrases on the tonic or the fifth. `Piece.texture()` decides which parts play in each bar. `TRACKS` is the library for menu, day and night: ten named pieces, each written from a fixed seed (`seededRandom`) with its own key, tempo, meter, pipes, opening and length, so a track sounds the same every time; `pickTrack` chooses at random, never one of the last `TRACK_MEMORY`. `windDown()` ends a piece early at the end of its phrase. `nextBar()` returns timed events (`{ t, dur, inst, midi, vel, pan }`).
  * `instruments.js` synthesizes them: Karplus-Strong lyre (cached per note, tuned with `playbackRate`), reed pipe, pan flute, drone, frame drum, horn, sistrum, plus a generated reverb and a gentle high-pass. `Studio` holds what all pieces share; each piece plays through its own `Band` so it can fade out while the next begins.
  * `music.js` schedules bars half a second ahead on the audio clock (look-ahead scheduling: steady timing even when frames stutter). `nextPiece()` plays a track for moods that have them, a new piece otherwise. Raiders and festivals take over at once (the old piece fades out); between calm moods a track that also belongs to the new mood plays on, and one that does not winds down to its ending. It leaves silence between calm pieces, plays a track by name (`play`, console and music lab), and can render any mood offline (`renderMood`) for WAV export and tests.
* The app picks the mood every frame (`App.musicMood()`): raiders or Caesar's legions on the map (the same danger music), then a recent festival, then night (the sky's lamps) or day; the main menu has its own. Victory plays festival music, defeat the night music.
* Checking what you cannot hear: `tests/e2e/music.html` plays each track and each mood, and renders every mood and measures peak and loudness and each instrument's tuning; the smoke test runs `App.musicSelfCheck()` in the built game.

## Adding things

* **Turning a new building**: it turns by itself if its art keeps to `draw.js` (boxes, roofs, polygons through `P()`, windows, doors): check it at every turn in `tests/e2e/artsheet.html?turns=<its key>`. Things painted on one face (a sign, a frieze, an inscription) go in `decal(nu, nv, fn)` with the face's outward side as written, art drawn in raw pixels about its middle only suits a building in `SAME_EVERY_WAY`, and a building whose facing the world decides gets a `turnRule()` reason (`sim/construction.js`). `tests/turn.test.mjs` draws it at every turn.
* **A new building**: add an entry to `data/buildings.js` (pick an existing `kind` if possible; `name` is the Latin name every message and panel uses, `en` the English one shown with it in the build menu, its tooltip and the panel title through `fullName`, and `PLURALS` its Latin plural for counted messages), add an art function in `render/buildingArt.js` (`ART` map, and a height in `HEIGHT`; the fishing buildings' art is in `render/waterArt.js`, the hippodrome's and chariot maker's in `render/hippodromeArt.js`), unlock it in `data/scenarios.js` (missions 5 and 6 list every building but the hippodrome's: a new building joins them unless it is held back). If it needs new behavior, add a case in `Game.updateBuilding()` and a module in `sim/`. Draw windows and doors with `windows()` / `door()` and they light up at night by themselves; torches go in `TORCHES` (`render/lighting.js`), flags in `FLAG_SPECS` (drawn with `flagPoles()`). Check the result in `tests/e2e/artsheet.html` and `tests/e2e/render.html` (`time=0.8` for night, `ladder=1` for a home of every level beside the city).
* **A new walker**: `data/walkers.js` + an effect case in `sim/services.js` (roamers) or a state in `sim/walkers.js` `onPathEnd()` (criminals: `sim/crime.js`, their waits end in `criminalAfterWait()`), words in `ui/walkerTalk.js`, a look in `render/walkerArt.js`.
* **A new house need**: add the field to `HOUSE_TIERS` (and its default in `L()`), measure it in `evaluateHouse()`, check it in `checkNeeds()`, explain it in `describeNeed()` (`ui/infoPanel.js`) and `tierNeeds()` (`ui/advisors.js`).
* **A new trade partner**: `TRADE_PARTNERS` in `data/scenarios.js` (`route: 'land' | 'sea'`, `pos: at(lon, lat)` where the city really is, `color` for its sails, caravans and dot), and a road or lane from its city into the network (`ROADS` or `LANES` in `data/empireRoutes.js`; or, to keep the Etruscan coast's way exact, a chain in `ROUTES_LL`, `data/empireGeo.js`): roads over land, lanes over water, which `tests/empire.test.mjs` and `tests/sites.test.mjs` check from every site, and which must not shorten any Etruscan route. A new site goes in `SITES` (`data/sites.js`) with roads or lanes joining it. Only give sea partners to scenarios whose maps have navigable water. A partner's yearly purchases for one mission go in the scenario's `demand` and `demandChanges` (on `DEMAND_TIERS`, `sim/tradeDemand.js`), never in its table, so other missions keep theirs; a small island city needs its island in `ISLANDS_LL` (Delos is drawn a little bigger than life).
* **A new soldier type**: `data/units.js`, a fort in `data/buildings.js` (`kind: 'fort'`, `unit`), a `RECRUIT_COST` in `data/goods.js`, art in `render/militaryArt.js`. A new enemy kind: `data/units.js` (side `enemy`, its `siege`), a look of its own in `render/militaryArt.js` (`tests/peoples.test.mjs` checks every land unit draws, each kind differently), and a place in a people's `mix`. A new people: `PEOPLES` in `data/peoples.js` (shares adding to 100, a `target`, `breaks`), and the missions or sites it raids (`PEOPLE_BY_MISSION`, `PEOPLE_BY_SITE`). A new ship: `naval: true` in `data/units.js`, its behavior in `sim/navy.js`, its art in `render/shipArt.js`.
* **Balance**: `config.js` first (difficulty levers: `data/difficulty.js`). Then `npm run sim -- --years 5` (add `--difficulty insane`, `--raids occasional --garrison`, `--size 256`) to see the effect without playing.
* **A new map size**: add it to `MAP_SIZES` and `MAP_SIZE_NOTES` (`world/mapgen.js`) and to the `map=` flag list in `core/debug.js`. `GameMap` allows up to 256x256 (paths in saves are packed as 16-bit indices).
