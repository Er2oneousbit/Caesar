# Architecture

How Colonia is put together, for whoever touches the code next.

## Big picture

```
            +------------------------- browser only --------------------------+
            |                                                                 |
 index.html |  main.js -> App (app.js) ---- Renderer (render/*)  canvas       |
 or dist/   |               |  \-------- UI (ui/*)            DOM widgets    |
            |               |  \-------- Input (input/*)      mouse/touch/keys|
            |               |  \-------- Sfx, Music (audio/*) WebAudio       |
            +---------------|-------------------------------------------------+
                            v
            +-------------- runs anywhere (browser AND Node) ----------------+
            |  Game (core/game.js)                                           |
            |    map (world/map.js)      typed-array tile layers             |
            |    buildings: Map<id, Building>   walkers: Map<id, Walker>     |
            |    units: Map<id, Unit> (soldiers + raiders), projectiles      |
            |    city: plain object (money, ratings, trade, gods...)         |
            |    systems: sim/*.js       pure functions of (game, ...)       |
            |    events: EventBus  ---> UI/audio/renderer subscribe          |
            +-----------------------------------------------------------------+
```

The simulation never touches the DOM. That single rule is what makes the headless tests (`tests/sim.test.mjs`), the balance simulator (`scripts/simulate.mjs`) and the live main-menu background all work.

## The main loop (`app.js`)

Each animation frame:

1. Add `dt * TICKS_PER_SECOND * speed` to an accumulator and run whole simulation ticks (capped at `MAX_TICKS_PER_FRAME` so a slow frame cannot snowball).
2. Keyboard and edge scrolling. Edge scrolling waits for a real pointer move on the current map (`input.mouse.game`): a menu or modal that vanishes under a still cursor only sends `pointerenter`, and its position must not read as "at the screen edge".
3. Render. The leftover fraction of a tick (`alpha`) interpolates walker positions so they glide at 60 FPS even though the sim runs at 12 Hz at 1x. `TICKS_PER_SECOND` only sets the real-time pace: all balance is per tick and per day. Walkers and soldiers count the tiles they walk (`walked`, modulo `STRIDE_WRAP`), and the art swings their legs from that, so steps match ground speed at every game speed and freeze when paused.
4. Refresh UI widgets (HUD 4x/second, info panel ~1.4x/second, advisors every 1.5 s, the Empire map every frame while it is open).

## The tick (`core/game.js`)

```
tick():
  time.advance()                          calendar, reports new day/month/year
  updateWalkers()                         movement + arrival logic (incl. ships
                                          and fishing boats: their waits end in
                                          boatAfterWait(), sim/fishing.js)
  updateMilitary()                        soldiers, raiders, the fleet and raider
                                          ships (sim/navy.js), towers, missiles
                                          and fire pots
  updateCriminals()                       prefects and soldiers catch criminals
                                          beside them; every 10 ticks prefects hunt
  for buildings whose phase == tick-of-day:
      kind-specific daily logic (house evolves, farm grows, market buys,
      shipyard builds or sends its spare boat, wharf carts its catch,
      navalia builds a liburnian...)
      updateServiceSpawns()               roaming walkers
      updateLaborAccess()                 can it hire? (housing within 40 road tiles)
      updateRisk()                        fire / collapse
      updateDiseaseRisk()                 homes: disease risk, outbreaks
  on new day:   labor, no-road notices (once per building, after 8 days
                without a road; sim/roadAccess.js), water, desirability
                (if dirty), stats, the city's
                entertainment base and wine sources, goods use on day 8,
                immigration, emigration, fires spreading, sick homes
                (spreading, calling physicians, recovering), home moods
                (day 8), caravans and ships, raid progress (a raid by sea:
                its days from the landing), training trips (sim/training.js
                updateDrill) and supply demand for barracks
                and the navalia
  on new month: food/goods consumption, wages & taxes, army pay, the
                governor's salary (sim/governor.js, last, so it never makes
                debt), raid
                warnings (by land or by sea, sim/navy.js seaRaidPlan)
                and launch, city mood, home moods, religion, ratings
                (then the month's crime flag is cleared), city health (and
                last month's grouped outbreak message), Emperor requests,
                the count of recent gifts, history, victory/defeat
  on new year:  tribute, ledger rollover, the year's salary against the
                governor's rank (favor), trade quotas reset, crime and
                disease counts
  then, on a new day: the crime roll (last, so on the 1st it sees the new
                month's home moods and counts toward the new month)
```

Buildings get a `phase` (`id % TICKS_PER_DAY`) so their daily work is spread over the 20 ticks of a day instead of spiking at midnight.

## Data model

* **Map** (`world/map.js`): one `Uint8Array`/`Int32Array` per layer, index `y * w + x`. Persistent layers: terrain, variant, road, aqueduct, rubble, fixedRoad, wall (wall/gate), roadblock (on road tiles: `ROADBLOCK.PRESENT` plus the bits of the walker groups it lets through; missing in older saves, which load without any). Derived layers (rebuilt, never saved): building ids, desirability, water coverage bits, road network ids, distance to water, **navigable** water (connected to the map edge; ships) with `navBody` (which navigable water a tile is, so warships and raider ships never leave theirs) plus `seaEntry`, and **fishing water** (`fishBody`: every body of water of `FISH_BODY_MIN` tiles or more, labelled) with its `fishingGrounds` (`computeFishing()`: from the terrain and the saved `variant` bytes only, no random draws, so every map stays as it was and old saves get grounds too).
* **Ruins** (`sim/ruins.js`): the rubble layer is only a flag; `game.ruins` maps a rubble tile to what stood there (a building name or a home's level name), why it fell (`RUIN_CAUSES`: fire, lightning, raidFire, riot, collapse, raid, raidWall) and the month and year. Every tile of a footprint shares one record, cleared tile by tile when the rubble is cleared or built over (`clearRuin`; an undo puts it back). Saves hold one entry per record with the tiles it still covers. Words only: the sim never reads it.
* **Building** (`sim/entities.js`): plain object. `b.def` is the static definition from `data/buildings.js`. Kind-specific fields: `house` (tier = housing level 0-20, pop, pantry, service timers (`police`: days of police cover from a prefect), `entBoth` two-show visits, `devolveDays` bad days in a row, `merged` for a 2x2 block of single-tile homes; for crime: `mood` (null while empty), `moodReason`, `moodTarget`, `hungerStreak`, `criminal` 0/1/2; for disease: `diseaseRisk`, `sick` days left), `noRoadDays`/`noRoadWarned` (days in a row without a road, and whether the one-time message went out), `stock`/`incoming` (storage, markets, workshops), `orders` (granaries and warehouses: per good `'accept'`, `'refuse'` or `'get'`), `emptying` (the Empty switch) and `orderNote` (what the last Get or Empty check found, for the panel), `shows` (venues; one count per kind in `SHOW_KINDS`, the hippodrome's races included), `hasWater`, `fertility`; shipyards and wharves: `mooring` (the water tile beside them, cached) and `waterSide` (for the art), a wharf's `boatId` and `catches`, a shipyard's `spareId`, `progress` and `boatsBuilt`; the fleet's buildings (on the shore, with `berth` and `waterSide` like a dock): a navalia's `stock`/`incoming` of timber, iron and linen, `progress`, `built` and `blocked`, a naval station's `rally`. Houses change footprint as they grow and split; they keep their id (and the anchor tile) when they do.
* **Linked buildings** (the hippodrome, `span: 3` in `data/buildings.js`): Colonia's footprints are square, so the 15 x 5 hippodrome is three 5 x 5 buildings, the `hippodrome` itself (staff, walker, shows, fire and collapse, info panel; its `parts` list the others) and two `hippodrome_part` (no staff, never burn or collapse; `main` points back, `section` 1 or 2 picks their stretch of the track's art). `linkedGroup()` / `mainOf()` in `sim/entities.js`: `removeBuilding()` takes the whole group, `computeAccessRoad()` takes a road beside any section (`footprintRect()`), a roamer passing a section looks after the main one, flames beside a section heat it, a burned or collapsed section leaves rubble over all 75 tiles whose record rebuilds the hippodrome, `planAction()` previews all three (`items[k].part`, with their `type` and art `state`) and `applyPlan()` builds them as one (one cost, one undo). The info panel shows the main section for a click on any part.
* **Walker**: plain object with `kind` = `roamer` (wanders serving buildings), `carrier` (goes somewhere and comes back), `traveler` (goes somewhere and vanishes), `ship` (like a traveler, but its path runs over water instead of roads: merchant ships over navigable water, fishing boats over their own fishing water) or `criminal` (protester, thief, rioter: `sim/crime.js`, with `hp` and the `home` it came from). Movement is always "stand on tile (x,y), walk toward (tx,ty), progress 0..1". A walker with `offRoad` (rioters, and prefects chasing them or walking back from a chase) follows a path over open land (`landPath`: A* with roads cheaper and trees dearer) and only plans again when a building or wall appears on it; `held` > 0 freezes a walker for a tick (a prefect and a criminal in a struggle).
* **Unit** (`sim/military.js`): soldiers and raiders are not walkers. They move freely over open land in continuous tile coordinates (tile centers at .5), fight, and are drawn live by `render/militaryArt.js`. `px/py` keep the previous tick's position so the renderer can interpolate. Ships of war are units too, with `naval` in `data/units.js` (`sim/navy.js`, drawn by `render/shipArt.js`): a liburnian has its `station` and berth `slot` (and a `ramCooldown`), a raider ship its `invasion`, `crew` (the warriors still aboard), fire `pots` and `waitTicks` before it sets out; both follow water routes (`path` over their `navBody`). `updateMilitary()` sorts them out of the land lists, so soldiers, raiders, towers and the crime code never see a ship, and runs them in `updateNavy()`. A Roman unit is `trained` or not (`sim/training.js`), and while on its way to a Military Academy or the Portus has `drill` (its id) and `drillDay`.
* **Reservations**: a cart on its way reserves room at its target (`incoming`; a Get cart reserves room at its own building, from the moment it sets off, for what it will bring back), settlers reserve beds (`house.incoming`), performers reserve a venue slot. `killWalker()` always releases them, so storage never overfills and houses never overbook.

Everything is serializable JSON, see `core/save.js`. Map layers are PackBits run-length coded then base64 (`"pb:..."`, or plain base64 when that is smaller) and walker/soldier paths are packed as 16-bit tile indices (`"u16:..."`; maps are at most 256x256, so every index fits). The save format is versioned (`SAVE_VERSION`, currently 13: 13 the governor (`city.governor`: `rank`, `salaryRank`, `savings`, `paidThisYear`; `city.gifts`: `recent`, `monthsSince`, `sent`, in place of `city.giftCooldown`; 12 is another change's); `upgradeGovernorV12()` gives an older save the mission's rank (a sandbox the middle one) at its own rate, no savings, the salary counted as paid for the months of the year already gone, and a gift still in the old six-month wait counted as one gift sent that long ago; 11 sea raids and the fleet (`military.seaRaids`, the switch; `navalDemand`; ship counts in `stats`; navalia, naval stations, liburnians and raider ships; an invasion's `sea`, `landing`, `landed`, `landedDay`; `upgradeNavyV10()` turns the switch on for older saves, adds the counts at 0, and leaves a raid the scouts already saw a raid by land); 10 the cloth industry (flax, linen and clothing; `upgradeClothV9()` gives older saves clothing at 0 in every market, the three goods at 0 in every warehouse and dock and a trade setting each, and every home clothing at 0 but Tenements and better, which start with `CLOTHING_GRACE_MONTHS` (3) of it so a loaded city has time to build the chain); 9 fish (a fifth food), shipyards, wharves and their boats, and the hippodrome; `upgradeFishV8()` gives older saves fish at 0 in every food list and a fish trade setting, hippodrome access and shows at 0; 8 ships waiting at the dock while dock workers carry goods both ways; 2 added the military, 3 the packing, 4 the 20-level housing ladder, 5 home mood and crime, 6 disease, 7 granary and warehouse orders, ruins (older saves load with rubble that has no record) and the original's five gods, 8 ships that wait at the dock (a moored ship's `unload`, `wants`, running `deal`, `mooredTick` and crane, a dock worker's export `claim`); `upgradeGodsV6()` runs first, on the raw data before anything is built from it, and renames Jupiter to Mercury and Vesta to Venus everywhere a god's key is stored (`city.gods`, the two temple types, every home's `religion`, priests' `god`, a sandbox scenario's unlock list), since the loader skips buildings of an unknown type; then `upgradeV4()` gives version 4 homes the crime fields, `upgradeV5()` gives version 4 and 5 homes the disease fields, and `upgradeOrdersV6()` turns older storage's `accept` flags into `orders` (Accept or Refuse, Empty off), `upgradeShipsV7()` gives a ship moored in a version 7 save (which traded everything on arrival and was logged then) nothing left to trade, so it casts off on the first tick without a second log entry (goods on a quay stay and are carted on), and the Game constructor fills in `city.crime`, `city.health`, any god a save lacks and `city.venusBoost`). Until 1.0 a release may refuse older saves (`MIN_SAVE_VERSION`, now 4), always with a readable message; fields added within a version get fresh defaults when missing. Campaign saves store only the mission id plus `difficulty`; sandbox saves store their whole scenario.

**Difficulty** (`data/difficulty.js`) is one table of levers per level (funds, risk, production, winter farm growth, immigration, mood, raid size/interval, raider strength, the Emperor's request size/interval/deadline, crime, disease). `Game` looks the level up once (`game.difficulty`, from `scenario.difficulty`) and each system reads its own lever; campaign missions get a level through `withDifficulty()` (`data/scenarios.js`), which also scales their funds.

## The genre mechanics, where they live

| Mechanic | File | Short version |
|---|---|---|
| Service coverage | `sim/services.js` | Roamers set per-house access timers (96 days; tax registration 48) on buildings within 2 tiles of each step. An entertainer from a venue with both kinds of show booked also sets that venue's `entBoth` timer. |
| Roaming | `sim/movement.js` | Never reverse, prefer straight, avoid recently walked tiles, stay within 13 tiles of home; prefects and engineers weigh each way by the worst fire or collapse risk along it (`streetRisk`, up to 11 times as much at the threshold), and their next round starts as the last one heads home (`sim/services.js`); never step onto a roadblock (`map.roadblock`) that does not let the walker's group through (`data/walkers.js` `ROADBLOCK_GROUPS`). Walkers following a path (to a destination or home) ignore roadblocks. |
| House levels | `sim/housing.js`, `data/housing.js` | 20 levels. Up one level at once when the next level's needs and the current level's `up` desirability are met; down one after `game.difficulty.devolveDays` bad days in a row. Four single-tile homes of a level may join a 2x2 block; homes grow into 2x2 / 3x3 / 4x4 at 11 / 15 / 19 (homes of their level or lower, then clear land, then gardens; partly covered homes break up) and split when they fall back, keeping a corner with a road in reach (pieces with no road stay vacant lots). Residents over capacity leave as homeless. |
| Entertainment | `sim/entertainment.js`, `sim/housing.js` | A home's score = the city-wide base (0-20 from the three seat kinds' coverage over the population, daily; a working hippodrome adds 100% coverage to the sum, still over `ENT_SEAT_KINDS` 3, so up to `ENT_BASE_MAX` 26) + points for each venue visited (+ a bonus when it had both kinds of show; the hippodrome's charioteer 30). A venue sends its walker only while staffed and booked; the chariot maker books the hippodrome's races (`racesRunning()`, which also lifts the prosperity target by `HIPPODROME_PROSPERITY`). |
| Fishing | `sim/fishing.js`, `world/map.js` | Shipyard: progress by staffing x production, a boat every `SHIPYARD_BOAT_DAYS`; the boat waits as the yard's spare until the nearest staffed boatless wharf on its water (by water route) takes it (ownership moves to the wharf, so it sinks with it). Wharf's boat: moored for (1.02 - staffing) x `BOAT_WAIT_DAYS` (not with no staff, not while the wharf holds `WHARF_FULL`), to the nearest ground by water, `FISH_DAYS` / production fishing, home, `FISH_CATCH` landed; the wharf ships it like a farm (`shipOutput`). Neptune's wrath: `sinkFishingBoats()`. Guards that keep a city with no fish exactly as before: market buyers want fish only when some storage holds it (and clothing likewise, wanted by Tenements long before a city makes any; the Emperor asks for flax, linen or clothing only while a building that makes it stands, so a city without the cloth industry draws its requests as before), Mercury gives `LAND_FOODS`, the Emperor asks for fish only while a wharf works, the capacity model leaves wharves out. |
| Immigration | `sim/population.js` | Mood >= 30 and free beds on the entrance's road network; groups walk in from the map edge. Past a 70-tile trip they ride a mule, up to 2x faster (big maps). |
| Labor | `sim/labor.js` | 32% of plebeians work; priorities first, then proportional shares. |
| Water | `sim/water.js` | Reservoir next to water fills; aqueducts flood-fill to more reservoirs; piped area feeds fountains/baths. |
| Desirability | `sim/desirability.js` | Every building radiates `[value, step, stepSize, range]`; terrain adds waterfront/tree bonuses. |
| Home mood | `sim/mood.js` | For crime only. Twice a month each home moves at most `MOOD_STEP` toward city mood + hunger streak + food variety + envy (the poorest levels in a rich city) + desirability + untaxed, and records its worst trouble. |
| Crime | `sim/crime.js`, `data/crime.js` | Daily from 300 people (off in missions with `crime: false`): the lowest-mood home that can still produce something; the chance falls on one line with city mood, x `difficulty.crime`, halved by police cover (a prefect within `POLICE_DAYS`). A protester stands about 4 days; a thief walks to a Forum/Senate (else a market) and steals on arrival (never more than the treasury holds); a riot burns its home and sends a mob overland at the most prized building within 40 tiles (`RIOT_TARGETS`), else the nearest listed one it can reach (`nearestReachableRiotTarget`, a search over open land), burning what it passes, for at most `RIOTER_MAX_DAYS`. Prefects and soldiers beside a criminal catch him; roaming prefects hunt thieves and rioters within 30 tiles, and one they cannot reach is skipped for `HUNT_RETRY_TICKS` (`walker.noChase`) while they keep their patrol. A family moving into an empty home starts at the city mood with a clean record (`newHousehold`); split-off homes keep their families' mood and record, joined homes the worst flag. Counts per year in `city.crime`. |
| Health and disease | `sim/disease.js`, `data/disease.js` | Each occupied home's health score (level up to 10, medicus/hospital 30/40/50, baths 15, barber 10, fountain water 10, 10 per food, at most 40 when hungry) sets how fast it builds `diseaseRisk` (x crowding, x `difficulty.disease`, halved in a staffed hospital's reach), daily on its own tick after fire risk, from 200 people (off in missions with `disease: false`). A physician's visit (the `clinic` effect in `sim/services.js`) resets it and cures. At `DISEASE_THRESHOLD` a 25% daily chance of an outbreak: a share of the residents die, the rest are `sick` for `SICK_DAYS` (no moving up: `updateHouse`; no settlers: `updateImmigration`, `seekHome`, `settlerArrive`; never taken over by a growing home). `updateSickHomes` (daily) heats the homes touching a sick one and rolls once per neighbor; `dispatchPhysician` sends a physician on his rounds, else one from a staffed medicus (`toSick`, then `treat` and `nextSick`), like `dispatchPrefect`. City health (`city.health.value`) moves `HEALTH_STEP` a month toward the residents' average score; shown only. One outbreak message a month, the rest grouped. Counts per year in `city.health`. |
| Fire/collapse | `sim/risk.js` | Daily risk growth at each building's rates (`riskRates`: a home's level, else its `fire`/`damage` data; 0 = never, which the info panel, the risk overlays and raiders also ask); prefects/engineers reset it; burning ruins heat the buildings beside them and may set them alight (once a day per building, `FIRE_HEAT_PER_DAY`, `FIRE_SPREAD_CHANCE`) and get doused. |
| Food & goods | `sim/production.js`, `sim/market.js`, `sim/storage.js`, `sim/storageOrders.js` | Producer -> cart -> workshop/granary/warehouse -> market buyer -> market vendor -> house pantry. What a cart does with a good follows its `kind` in `data/goods.js`: a `raw` good goes to a workshop whose recipe uses it first, and warehouses forward `RAW_TYPES` to workshops running low. Linen is `raw` for that reason although a workshop makes it, so the cloth chain (Flax Farm -> Linen Maker -> Clothing Maker -> warehouse) needs no code of its own. Storage orders (Accept, Refuse, Get per good, and Empty) only steer deliveries in; `updateStorage()` sends a granary's or warehouse's one cart a day: Empty, else Get (a `'collect'` cart walks out empty and brings the load home), else a warehouse's routine supply. Get never takes from storage on Get for that good. |
| Money | `sim/economy.js`, `sim/loans.js` | Monthly wages and taxes (only houses a tax collector visited), yearly tribute; loans from Rome and their monthly repayments (right after wages and taxes). |
| Advisors' coverage | `sim/coverage.js`, `ui/coverageInfo.js`, `data/advisors.js` | Not a system: read-only reports for the Health, Education and Entertainment advisors (`healthReport`, `educationReport`, `entertainmentReport`) and the Overview's crime line (`crimeNow`). Per building type: built, staffed, working, reach (residents with the access timer, or in a hospital's area), and need / served (residents of homes whose next level asks for it, and of those, the ones that have it). Venue seats come from `seatCoverage` (`sim/entertainment.js`, the same function the daily base uses). The advice picks are pure functions of those tallies (`pickHealthAdvice`, `pickEducationAdvice`, `pickEntertainmentAdvice`, `venueNeedingShows`); `ui/coverageInfo.js` words them and `data/advisors.js` holds the twelve coverage words and the health verdicts. Reading them changes no state and draws no random numbers (tested). |
| Goods book | `sim/goodsLedger.js` | Bookkeeping only: per good, units made, used, imported and exported this month (`city.goodsFlow`), last month's in `city.goodsFlowLast` for the Production advisor (`ui/production.js`). |
| Trade | `sim/trade.js` | Open routes; land partners send caravans to a warehouse, sea partners send ships to a Dock, where a ship waits while it trades: its manifest is fixed on mooring, a crane lands imports on the quay (paid as they land), the Dock's 1 to 3 workers (by staffing) cart quay goods to storage and fetch exports from staffed warehouses within `DOCK_REACH` road tiles (claims keep every good at its export level; paid when handed aboard), and the ship casts off when both sides are done, at `SHIP_MAX_STAY_DAYS`, or when the Dock is lost; one trade-log entry a visit; per-good import/export levels and yearly caps. |
| Military | `sim/military.js` | Barracks equip recruits from delivered weapons/arrows/horses and send them to forts; soldiers hold BFS formation spots around their fort or rally point and engage raiders in their guard radius; raiders follow a Dijkstra flow field from every building (walls cost extra) and siege what they reach; towers shoot; invasions are scheduled, warned, launched, repelled or withdraw with plunder. |
| Sea raids and the fleet | `sim/navy.js` | At the scouts' warning, `seaRaidPlan()`: with the switch on and a `seaEntry`, a roll on its own `RNG` (`${seed}:searaid:${raid number}`, so the shared stream is untouched and a raid by land draws what it always did) below `SEA_RAID_SHARE` sends it by sea if `findLanding()` finds open shore on the sea entry's water whose raider walk to the nearest home (`fillField` from homes) is closest to `LANDING_WALK`. `launchSeaInvasion()`: `RAID_SHIP_CREW` a ship from the sea entry, 30 ticks apart, by water A* to tiles by the landing; on arrival `landCrew()` spawns the crew as ordinary raiders and the raid's clock (`seaRaidDays`) starts. While at sea a ship shoots a liburnian in range, else throws a pot (`RAID_SHIP_POTS`) at a fishing boat (killed) or the nearest building with a tile in range (`damageBuilding(..., { fromSea })`, fire risk). The Navalia (`updateNavalia`) builds a liburnian from `LIBURNIAN_COST` in `NAVALIA_BUILD_DAYS` while a staffed station on its water has a free berth (`navalNeed` puts it before workshops in `findDeliveryTarget` and warehouse supply); stations berth `STATION_CAPACITY`, deploy like forts (`deployStation`, water within 2 tiles of the click), and a lost one hands its ships to another station on the same water or lays them up (`stationLost`). Ships steer straight while every tile the line crosses is their water (`clearWater`, a grid walk; through a corner both tiles beside it), else along a water A* route re-planned every 20 ticks toward a moving goal; a ship somehow off its water (`u.body`) makes for the nearest tile of it. |
| Training | `sim/training.js`, `sim/military.js`, `sim/navy.js` | A Military Academy or a Portus trains only at full staff (`trainsNow`: `efficiency >= 1`, a road, a Portus its water); "nearest" is the larger axis distance between the buildings' middles, the lower id on a tie. Every Roman unit has `trained`. `updateBarracks` asks `recruitDetour()` for the academy nearest the recruit's fort: the recruit walks there in state `toAcademy` (`academy` = its id), `recruitAtAcademy()` marks him `trained` on arrival and sends him on as `toFort`, and `recruitArrive` hands the flag to his unit. A liburnian launched with a training Portus on its station's water (`portusFor`) starts with `drill` set. `updateDrill()` (daily, from `militaryDaily`; nothing at all without an academy or Portus) sends each idle fort's or berthed station's first untrained unit (`drill`, `drillDay`) `DRILL_PER_POST` at a time, calls everyone home on a raid or a deployment, and gives up a trip after `drillDays` (at least `DRILL_MAX_DAYS`, twice the straight-line walk for a far school; `drillWait` on the post). A trained recruit is counted at his academy (`trainedHere`, `soldiersTrained`) only when he joins his fort (`recruitTrained`). The walk itself is `drillMarch()` in `updateRoman` (to the academy's road, over open land) and `rowToPortus()` in `updateLiburnian` (to its berth); `drilled()` sets the flag. Effects: `unitDefense()` (type defense + `trainedDefense`, + `holdDefense` while `holdingPosition()`: standing still, idle at his post or with his raider in reach, not on a trip) feeds `rollDamage`; `missileDamage()` scales a missile by `holdMissile` as it lands; `shipSpeed()` and `ramOf()` for a trained crew. `battleStrength()` is what a unit counts for in a distant battle (`strength`/`trainedStrength` in `data/units.js`). |
| Horse breeding | `sim/production.js` | A ranch's herd grows 2 -> 8 with staffed days; foaling rate scales with herd size. |
| Gods | `sim/religion.js` | Mood from temple coverage (staffed temples, each counting its `templeWeight`: a large temple 2) + festivals + oracles; blessings and wrath. A god that strikes stays `angered` until its mood is above `GOD_CALM_MOOD`; Mercury and Venus (`harderWrath` in `data/gods.js`) strike harder if angered again, unless the scenario says `majorWrath: false`. Venus's part of the city mood is `city.venusBoost` (`computeSentiment`). |
| Ratings / win | `sim/ratings.js` | Culture, prosperity, peace, favor drift toward targets (culture and prosperity by at most `CULTURE_STEP` / `PROSPERITY_STEP` a month, peace `PEACE_PER_MONTH` while the mood is good); goals checked monthly. |
| Campaign pace | `sim/pace.js` | Not a system: the fewest months each goal can take under the rates above and `immigrationPerDay` (`sim/population.js`). Each mission's `paceYears` (`data/scenarios.js`) is held to it by a test; `npm run sim -- --pace` prints it. |
| Campaign capacity | `sim/capacity.js` | Not a system: how many people a mission's buildings can employ. `planCity` lists the buildings a sensible city of P people puts up (services by walker `roam`, farms and granaries by what P eats, temples by `PEOPLE_PER_TEMPLE`, venues by the level's entertainment, industry only for the homes' goods and what partners buy (with each workshop's inputs made at home down the whole chain: clothing's linen and that linen's flax; `goodsAvailable` passes over the unlocks until nothing new is made, so a three-step chain is found in any order), a garrison where there are raids), every home at the best level whose residents work; two profiles say how generously (`LEAN`, `SENSIBLE`: a careful player's density and spare farms, checked by play). The employment ceiling is the largest P whose jobs keep unemployment at or below `UNEMPLOYMENT_MOOD_FREE`; `landCeiling` checks the map can house and feed them. A test holds each mission's population goal to the sensible ceiling and the land (missions 3 to 7 are listed exceptions, see the ROADMAP); `npm run sim -- --capacity` prints the table. |
| Emperor | `sim/emperor.js` | Periodic requests with deadlines; gifts from the governor's savings (`GIFT_SIZES`: a share of the savings plus a base, favor by how many gifts in the last 12 months, `city.gifts`). |
| Governor | `sim/governor.js`, `data/ranks.js`, `ui/governorInfo.js` | `city.governor`: the rank (`scenario.rank`: one per mission, picked in the sandbox setup), the rate drawn (`salaryRank`), personal `savings` and `paidThisYear`. `paySalary()` monthly, only when the treasury covers it; `salaryNewYear()` judges the year's pay (`rankForYearPay`, `salaryFavor`). `donate()` moves savings to the treasury (ledger `donations`, out of `ledgerNet`). Savings cross missions through the app's progress record (`storeCampaignSavings`, `campaignSavings`; `new Game({ savings })`). Residences are `kind: 'residence'` (one at a time, `checkBuilding()`; first in `RIOT_TARGETS`). `scripts/simulate.mjs` draws no salary unless `--salary`. |

## Rendering (`render/`)

* **Projection**: tile (x, y) top corner at world pixel `((x - y) * 32, (x + y) * 16)`. Camera scale = zoom x devicePixelRatio; everything is drawn in device pixels for crisp art.
* **Camera** (`camera.js`): `zoomIndex` is the zoom level the player picked; `zoomF` is the zoom shown, which eases to the level in about 0.2 s with the point under the cursor pinned. Also a fling (drag velocity that decays) and `glideToTile` (eased travel, used by messages, advisors, the minimap and Home). `centerOnTile` and setting `zoomIndex` stay instant (loads, tests). `smooth = false` (reduced motion) makes everything instant. `update(dt)` runs once per frame from the renderer.
* **Sprites**: every piece of art is a `spec` (size, anchor, draw function) rendered once per zoom level into an offscreen canvas (`sprites.js`). Art is procedural (`terrainArt.js`, `buildingArt.js`) using the tiny iso kit in `draw.js` (boxes with wall texture and contact shadows, tiled roofs with eave shadows, columns, windows with optional shutters and flower boxes, trees). Sprites are made for the zoom LEVEL and remember their scale `s`; while a zoom eases, `blit()` stretches them by `scale / s` (building strips snap to whole pixels so they do not show seams). New sprites get about 8 ms per frame (`spriteBudgetMs`); past that the cache borrows the other kept zoom level's copy, so a zoom never stalls while hundreds of sprites are drawn, and they sharpen over the next few frames.
* **Draw calls**: keep them down in the per-tile passes. Chromium flushes a canvas mid-frame past a few thousand draw calls, which roughly doubled the frame time when zoomed out, so edge blends are painted into the ground tile's sprite (`groundBlendSpec`) instead of drawn as a second sprite. Test zoomed-out views (`zoom=0`) after adding anything per tile.
* **Depth sorting**: flat things (terrain, roads, rubble) draw first. Everything tall is sorted by the x + y of its front point. Multi-tile buildings are cut into half-tile-wide vertical **strips**, each sorted by the front-most footprint tile it covers. That is what lets a walker pass correctly in front of and behind a colosseum with a simple sort.
* **Overlays** (`overlays.js`): tile tints and info columns; non-relevant buildings drawn as flat footprints. The crime overlay's columns and words come from `ui/crimeInfo.js`, the health overlay's (disease risk, sick homes in `SICK_COLOR`) from `ui/healthInfo.js`; the Problems overlay (`ui/problems.js`) puts sick homes and homes in unrest ahead of what a home lacks.
* **Building sprite keys** are `b:{type}:{size}:{variant}:{state}` (`buildingKey()` in `renderer.js`; `state` from `artState()`: a home's level, a farm's growth...), then `:sick` for a sick home (drawn a little pale with a pale cloth on a pole, `sickSign()` in `buildingArt.js`), then the snow suffix `~n{level}`, which stays last so a look change can drop sprites by suffix.
* **Fishing and races** (looks only): a fishing boat (`drawFishingBoat()`) shows its state (sail up under way, the net cast with a ring of floats while fishing, a basket of fish on the way home); gulls over each fishing ground (`drawGulls()` in `waterArt.js`, `Renderer.drawFishingGrounds()`, drawn still with reduced motion). The hippodrome's three sprites share one design (`hippodromeArt.js`, state = section). While races run, three chariots lap the spina (`Renderer.raceItems()`): each is queued just after the strip of its section's sprite that holds it (strips are screen columns drawn at their front tile's depth), or the track would paint over it. The charioteer and a chariot maker's team are drawn as a chariot and pair (`drawChariot()`). The shipyard's art state is its water side plus the hull on the slip (none, ribs, planked); the wharf's its water side plus baskets of fish while it holds a catch.
* **Walkers** are drawn live each frame (`walkerArt.js`), not cached, so they have no sprite keys. A walker type's `item` picks what it carries; the criminals have their own: a protester shakes a `placard`, a hooded thief carries a `sack`, a rioter waves a flickering `torch` (the raised arms bob with the clock, visual only).
* **Carts** show their cargo (`render/cargoArt.js`): each good has its own item (sacks of wheat, crates of vegetables and fruit, baskets of olives and grapes, joints of meat, clay lumps, logs, iron ingots, marble blocks, pots, pale oil and dark wine amphorae, tables and chairs, shields with spears, sheaves of arrows, bundles of flax with blue flowers at their heads, bolts of linen, stacks of folded clothes in two dyes) in a `layout` (`pile`, `row` or `layers`); a good missing from `CARGO_ART` gets a block in its `GOODS` color. The load shows as 1 to 4 items against what the cart holds (`cargoLevel`), and what it holds depends on who sent it (`cartCapacity`: a farm's wagon `FARM_CART_LOAD`, a warehouse's single lot `CART_CAPACITY`, everyone else `CART_LOAD`), so the renderer passes the sending building's def to `drawWalker`. A farm's cart is a longer four-wheeled wagon drawn by an ox; horses (`LED_GOODS`) are led on a rope behind the drover, one per 100 units, and a ranch's drover walks home with only the rope. A caravan's mule carries plain bales on its way in and, on its way out, the goods it bought (`walker.packs`, set by `caravanArrive()`; art only, the sim never reads it; saved with the walker, and a save without it just shows bales). All of it is a few shapes per item, drawn live; `tests/e2e/artsheet.html?carts=1` shows every good at two loads, both facings.
* **Life in the picture** (visual only, never touches the sim): buildings cast soft shadows to the lower right (drawn after the ground, before objects; `shadowLength()` in `buildingArt.js`); new buildings rise out of the ground with a dust puff; forests sway using 5 cached wind frames whose phase rolls across the map; water glints; working fountains spray; fires glow and throw embers; homes smoke; smithies throw sparks. `ambient.js` draws drifting cloud shadows and passing birds. Settings can turn the ambient layer off, and the OS reduced-motion preference disables all decorative motion.
* **Live details** (`liveArt.js`): drawn every frame on top of their building as `K_EXTRA` items right after its strips: flag cloth (the sprite only has the poles when drawn with `live = true`; `FLAG_SPECS` in `buildingArt.js` lists every flag), shoppers along the front of a stocked market, spectators in theaters and arenas while a show is booked (seats hidden by the stage or the arena floor are skipped), the temple altar fire.
* **Terrain**: 8 ground variants per land type. Where two kinds of ground meet, a wavy fringe of the stronger one (forest floor > grass > meadow > sand > rock, `BLEND_RANK`) is painted onto the weaker tile. The packed blend code per tile is cached (`Renderer.blendAt`) until `map.revision` changes.
* **Order of a frame**: ground, building shadows, sorted objects, particles, cloud shade and birds, then the **night** (`lighting.js`: the scene is multiplied by a half-resolution light map filled with the sky tint plus warm pools of light, then window/torch/fire glows are added), then **rain/snow/lightning** (`weather.js`), then the red **no-road signs** (`drawNoRoadSign()` in `liveArt.js`, over every building in view for which `lacksRoad()` holds; never smaller than its zoom-1 size, about 20 CSS px across, shown under overlays too; `stats.noRoad` counts them), then tool previews, radius hints and selection outlines, so those are never darkened. A building ghost on a spot with no road it could use is drawn in the warning color (its own sprite key, `...:noroad`, before the snow suffix; `tintedSpec()`), with the edge tiles where a road would serve it picked out (`accessEdgeTiles()`; `stats.ghostNoRoad`, `stats.roadEdges`), and `ui.js` puts the warning by the cursor in the tooltip's `warn` style.
* **Day, season, weather** are derived per frame in `Renderer.updateEnvironment()`: time of day from `game.time.totalTicks` (`dayTime`, `DAY_TICKS`), the season palette from `game.time.month` and the snow cover level (`seasonPalette(month, snow)`; `MONTH_LOOK` places each month among the four looks, and ground/tree/blend sprite keys end in `~p{look}[n{snow level}]`, building and rock keys in `~n{level}` while snow lies), and the weather state machine advanced by the game ticks that passed (so it pauses with the game). Seasons are calendar data (`sim/time.js` `seasonOf`, `SEASON_NAMES`, `GameTime.season()`; Dec-Feb winter, Mar-May spring, Jun-Aug summer, Sep-Nov fall); `weather.js` re-exports them. The weather draws a new spell when the season changes and `seasonalKind()` keeps rain and storms out of winter and snow out of the other seasons; `Renderer.attach()` calls `weather.reset()` so a new or loaded game opens clear and without snow. Snow **cover** (`weather.cover`, 0..1) builds while it snows and melts after (slowly in winter, fast in spring); it is quantized to `coverLevel` 0..3 with a little hysteresis, and the art bakes it into the sprites (white ground, snow-capped trees and rocks, snow on roofs via `setRoofSnow()` in `draw.js`, white fields), so there are no extra draws per frame. A **look change** (new month or snow level) is prepared, then swapped: `SpriteCache.get(key, spec, fallback)` keeps returning the old look's sprite while the new one is drawn within a 4 ms budget per frame (`pending` counts what is missing); the first frame that ends with nothing pending drops the old sprites (`finishLookChange`), so the next frame shows the new look whole. When changes overlap (snow deepening again before the last level is ready), `lookStep()` keeps the complete old look as the stand-in and drops the half-made one. A new or loaded game switches at once (`lookHard`). Window positions for night lights come from the art itself: `draw.js` records where `windows()` and `door()` put openings when the art is drawn into `recordingContext()`.
* **Coverage hints**: clicking a well/fountain/reservoir, or placing one, paints its supply area (dark blue) over the area already covered by that kind (pale blue, read from the sim's water layer). **Water hints** (`waterHintLayers`): while a tool is in hand, the water already there is tinted faintly under everything else: with the Housing tool, well water (palest) and fountain water (a stronger blue); with a building that needs piped water (fountain, baths), the reservoirs' piped area. Each tile is filled once with its strongest layer, each layer gets a thin outline, and tiles the coverage preview paints are left to it (`drawWaterHints`, counts in `stats.waterHint`).
* **Aqueducts** (`terrainArt.js` `aqueductSpec`): cached sprites keyed by their connection mask (`aqueductMaskAt`: the low four bits are the connections, the next four mark which of them are reservoirs, where the channel steps down to the rim) and by whether the tile is a road (a straight aqueduct over a road is drawn as a bridge with one wide arch).
* **Temples** (`buildingArt.js` `TEMPLE_LOOKS`): one look per god (roof, walls, pediment and emblem, a piece in front). The pediment is the god's color (`GODS[g].color`, which its priests wear), and no two roofs or pediments are near the same color (a test holds them apart), so the five read apart in the build menu's small icons.
* **Military layer** (`militaryArt.js`): walls/gates are cached sprites keyed by their neighbor mask (like aqueducts); soldiers, raiders, arrows, sling stones, fire pots and rally flags are drawn live each frame and depth-sorted with everything else. Ships of war (`shipArt.js`: the liburnian's two banks of oars stroke with the distance rowed, its sail furled in battle and at rest; the raider ship shows the warriors still aboard) are drawn the same way; the renderer keeps where each was drawn (`shipSpots`) so a click picks one (`pickShip`) for its panel. A selected naval station shows the water its squadron guards (`drawSeaGuard`). The Navalia and the Naval Station are cached sprites (`navyArt.js`), turned to the water like the dock (`state` = `waterSide`, plus the hull on the navalia's slip).
* **Empire map** (`ui/empireMap.js` draws it, `ui/empire.js` is the full screen): one renderer for the Trade advisor's small map (a snapshot) and the Empire screen (redrawn every frame), in a 100 x 60 map-unit space. The geography is `data/empireGeo.js`: coasts, islands, gulfs, rivers, mountain rows and region names written as longitude and latitude and projected equirectangularly (10 W to 37 E, 48 N to 26.5 N, so a degree of longitude is about 0.76 of one of latitude, true near 40 N); `at(lon, lat)` places a city (`pos` in `TRADE_PARTNERS`, `HOME_POS`, `ROME_POS` all use it) and `isLand(p)` answers land or water by point in polygon (the sea ring less the islands, plus the Red Sea gulfs and lakes). Each partner's route is a centripetal Catmull-Rom curve through its waypoints in `ROUTES_LL` (`routePath(id)`, cached, with the distance run at each point), which keep caravans on land and ships on water; the waypoints are written for the province's place, so moving `HOME_POS` means moving them too, and a test walks every curve. Names are placed last (`placeLabels`): each on the first side of its marker where it hits no other name or marker. Travelers are read from timers the sim already keeps, never simulated: `empireTravelers(game)` puts a caravan or ship on its route for the last `tripDays(id)` days before the route's `nextVisit` (10 to 32 days by the route's length, never more than the shortest gap between visits, so a route has at most one traveler out), positioned by the share of the trip done along the curve, with the day's fraction from `time.tick` so it glides. Until a route's first trader has called (`visits` 0) the trip is at most `FIRST_VISIT_DAYS` (`sim/trade.js`): that trader set out the day the route opened, so it starts at its city rather than partway along. A scouted warband (`military.warned`) closes in from its compass side over the 3 months before `nextRaidMonth` (one coming by sea, `warned.sea`, sails in a longship on the nearest side round from it that is sea); raiders in the province show at the city. It is pure (tested in node: `tests/empire.test.mjs`, including that reading it changes no state). Figures and labels grow on small canvases (`figureScale`) and clicks are tested against the middle of a figure as drawn (`figureCenter`). The screen is modal kind `empire`: like the Advisors the game runs behind it and the keyboard shortcuts work (`App.blockingModal`); its side panel sections are rebuilt only when their text changes, and not while a press inside the panel is held (the days tick by every second or two, and a button rebuilt between press and release would never get its click).
* **Map gates** (`liveArt.js` `drawMapGate`, `K_GATE` items): a stone gateway over the Imperial road at `map.entry` (green pennants) and `map.exit` (red), with torches at night. Mapgen lays the road straight in from the edge for `ROAD_STUB` tiles at each end, so `map.entryDir` / `map.exitDir` (saved with the map) always point straight in and the gates face the edge; `mapGateOffset()` stands the pillars across the road (older saves work the direction out from the roads around the tile); each gate is two items (back pillar, then lintel and front pillar) so walkers pass between them.

## Audio (`audio/`)

* **Sound effects** (`sfx.js`): a few oscillators or a noise burst per sound. The app suspends the audio context while the tab is hidden.
* **Starting the sound**: browsers hold audio back until a user gesture. `App.tryAutoplay()` creates the context at boot (and when a background tab becomes visible) if the music would be heard; where autoplay is allowed it simply runs. Otherwise the main menu shows the **title gate** (`ui.js` `showAudioGate`, `menus.js` `titleGate`): its click, tap or key press starts the menu music, and a short guard afterwards swallows the rest of that gesture (a double-click's second click, a held key's repeats) so no menu button is pressed by it. Unlock listens to `pointerdown`, `pointerup`, `touchend`, `click` and `keydown` (a touch only counts on its release); the context's `statechange` drops the gate whichever way the sound started.
* **Music** is generated, never recorded, in three layers:
  * `composer.js` writes the notes and nothing else (pure, deterministic for a random source, tested in node). A `Piece` has a mood (tempo range, meters, modes, keys, lead instrument, drum and lyre styles, the silence after it, a target length), an opening (`INTRO_STYLES`: who starts), and a form built to the target (a few minutes): the opening, then rounds of 4-bar sections repeated until it is long enough (A the theme, A2 moved up or down, B a higher answer, C a calmer contrast on the other pipe with a thinner accompaniment, an interlude for the lyre alone, A3/A4 ornamented), then an ending (battle music has none). A one-bar theme returns varied in the A sections; harmonies are perfect fifths under a drone; melodies move mostly by step, put chord tones on strong beats and long notes, and end phrases on the tonic or the fifth. `Piece.texture()` decides which parts play in each bar. `TRACKS` is the library for menu, day and night: ten named pieces, each written from a fixed seed (`seededRandom`) with its own key, tempo, meter, pipes, opening and length, so a track sounds the same every time; `pickTrack` chooses at random, never one of the last `TRACK_MEMORY`. `windDown()` ends a piece early at the end of its phrase. `nextBar()` returns timed events (`{ t, dur, inst, midi, vel, pan }`).
  * `instruments.js` synthesizes them: Karplus-Strong lyre (cached per note, tuned with `playbackRate`), reed pipe, pan flute, drone, frame drum, horn, sistrum, plus a generated reverb and a gentle high-pass. `Studio` holds what all pieces share; each piece plays through its own `Band` so it can fade out while the next begins.
  * `music.js` schedules bars half a second ahead on the audio clock (look-ahead scheduling: steady timing even when frames stutter). `nextPiece()` plays a track for moods that have them, a new piece otherwise. Raiders and festivals take over at once (the old piece fades out); between calm moods a track that also belongs to the new mood plays on, and one that does not winds down to its ending. It leaves silence between calm pieces, plays a track by name (`play`, console and music lab), and can render any mood offline (`renderMood`) for WAV export and tests.
* The app picks the mood every frame (`App.musicMood()`): raiders on the map, then a recent festival, then night (the sky's lamps) or day; the main menu has its own. Victory plays festival music, defeat the night music.
* Checking what you cannot hear: `tests/e2e/music.html` plays each track and each mood, and renders every mood and measures peak and loudness and each instrument's tuning; the smoke test runs `App.musicSelfCheck()` in the built game.

## Adding things

* **A new building**: add an entry to `data/buildings.js` (pick an existing `kind` if possible), add an art function in `render/buildingArt.js` (`ART` map, and a height in `HEIGHT`; the fishing buildings' art is in `render/waterArt.js`, the hippodrome's and chariot maker's in `render/hippodromeArt.js`), unlock it in `data/scenarios.js` (missions 5 and 6 list every building but the hippodrome's: a new building joins them unless it is held back). If it needs new behavior, add a case in `Game.updateBuilding()` and a module in `sim/`. Draw windows and doors with `windows()` / `door()` and they light up at night by themselves; torches go in `TORCHES` (`render/lighting.js`), flags in `FLAG_SPECS` (drawn with `flagPoles()`). Check the result in `tests/e2e/artsheet.html` and `tests/e2e/render.html` (`time=0.8` for night, `ladder=1` for a home of every level beside the city).
* **A new walker**: `data/walkers.js` + an effect case in `sim/services.js` (roamers) or a state in `sim/walkers.js` `onPathEnd()` (criminals: `sim/crime.js`, their waits end in `criminalAfterWait()`), words in `ui/walkerTalk.js`, a look in `render/walkerArt.js`.
* **A new house need**: add the field to `HOUSE_TIERS` (and its default in `L()`), measure it in `evaluateHouse()`, check it in `checkNeeds()`, explain it in `describeNeed()` (`ui/infoPanel.js`) and `tierNeeds()` (`ui/advisors.js`).
* **A new trade partner**: `TRADE_PARTNERS` in `data/scenarios.js` (`route: 'land' | 'sea'`, `pos: at(lon, lat)` where the city really is, `color` for its sails, caravans and dot), and its route's waypoints in `ROUTES_LL` (`data/empireGeo.js`): roads over land, lanes over water, which `tests/empire.test.mjs` checks. Only give sea partners to scenarios whose maps have navigable water.
* **A new soldier type**: `data/units.js`, a fort in `data/buildings.js` (`kind: 'fort'`, `unit`), a `RECRUIT_COST` in `data/goods.js`, art in `render/militaryArt.js`. A new ship: `naval: true` in `data/units.js`, its behavior in `sim/navy.js`, its art in `render/shipArt.js`.
* **Balance**: `config.js` first (difficulty levers: `data/difficulty.js`). Then `npm run sim -- --years 5` (add `--difficulty insane`, `--raids occasional --garrison`, `--size 256`) to see the effect without playing.
* **A new map size**: add it to `MAP_SIZES` and `MAP_SIZE_NOTES` (`world/mapgen.js`) and to the `map=` flag list in `core/debug.js`. `GameMap` allows up to 256x256 (paths in saves are packed as 16-bit indices).
